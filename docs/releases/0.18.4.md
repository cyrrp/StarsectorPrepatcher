# Отчёт о выпуске 0.18.4

> Project home:
> [StarsectorPrepatcher — overview, installation and downloads](https://github.com/kirpoly/StarsectorPrepatcher)

## Итог

Выпуск добавляет совместимость с Java 27 без Faster Rendering и для нового/старого устройства FR
без allowlist версий или checksums. Официально поддерживаются Java 17 и проверенная Miko Java
`27+22`; для более новой JVM выполняется та же проверка возможностей без заявления поддержки.

Без FR агент выбирает `JAVA27_STANDARD` по фактическим JVM arguments: в них нет `fr.agent.jar`,
legacy `AppClassLoader` и `fr.jar` в classpath. Наличие неиспользуемых файлов FR на диске не имеет
значения. Prepatcher остаётся последним agent, исправляет запрещённые обфускатором имена в исходных
game bytes и затем применяет единый pipeline обычным способом.

На Java 27 новый FR подтверждается синтетическим `com.fs.*` class с недопустимым именем
`while.new`: ранее зарегистрированный agent должен одинаково исправить declaration и call, не
изменить тела методов, передать итоговые bytes observer'у и позволить JVM определить class. Старый
FR подтверждается structural data-flow проверкой `AppClassLoader` и живым вызовом
`findBytecode("com/fs/starfarer/api/Global.class")` через внедрённый pre-define bridge. Если FR
заявлен конфигурацией, но соответствующая проба отвергнута, `premain` пишет причину и завершает
запуск до игровых targets. Отсутствие активного FR является штатным профилем, а не ошибкой.

Исходные game bytes и старый FR оставляют запрещённые имена вроде `while.new`, которые Java 17
принимала с выключенной проверкой. В обычный Java 27 pipeline и legacy bridge теперь встроен общий
точечный length-preserving repair constant pool: он согласованно меняет declaration/reference на
`while_new` до общего pipeline и `defineClass`, не трогая method bodies, descriptors или frames.

Та же нормализация затрагивает поля UI рынка: `if.new$class` становится `if_new$class`, а
`String.interface$float` — `String_interface$float`. Trade и market-overview matchers теперь
принимают ровно один вариант из соответствующей raw/repaired пары, сохраняют точный descriptor и
используют выбранное имя во всех добавленных чтениях и postconditions. Это устраняет два
`SKIPPED_STRUCTURAL` и не ослабляет fail-closed проверку будущей структуры класса.

## Transformation surfaces и composition

- `JAVA27_STANDARD`: в исходных game bytes исправляются точные нелегальные `CONSTANT_Utf8` member
  names, после чего bytes поступают в единый pipeline; отдельной FR surface нет.
- `FR_AGENT_CHAIN`: только временный synthetic probe class; observer удаляется в `finally`.
- `FR_PREDEFINE_BRIDGE`:
  `com/genir/renderer/loaders/ClassTransformer.transformBytes(Ljava/lang/String;[BLjava/util/List;)[B`,
  единственный итоговый возврат bytes после цикла `ClassConstantTransformer.apply`. Вызов
  `BiFunction<String,byte[],byte[]>` берётся из `System.getProperties()` непосредственно перед
  return. `AppClassLoader.findBytecode/findClass` проверяются как обязательная upstream/downstream
  data flow поверхность. После transformations FR и до pipeline исправляются только точные
  нелегальные `CONSTANT_Utf8` member names в пространствах игровых классов; длина constant pool и
  все индексы сохраняются.
- Local Resources:
  `com/fs/starfarer/api/impl/campaign/submarkets/LocalResourcesSubmarketPlugin.`
  `createTooltipAfterDescription(Lcom/fs/starfarer/api/ui/TooltipMakerAPI;Z)V`, label сырого
  fallback. После label находится точный `FrameNode(F_SAME)`; locals/stack не меняются, writer
  остаётся `COMPUTE_MAXS`.

Все прежние transformers собраны в один `OrderedTransformerPipeline`. Следующий stage получает
bytes предыдущего, `null` сохраняет текущее состояние, а необработанная ошибка откатывает весь
class к входу. Порядок закреплён metadata и соответствует
[`COMPATIBILITY.md`](../COMPATIBILITY.md). Presentation и structural changes продолжают применять
совместные ownership/mask postconditions; frame-fix входит в существующий
`localResourcesTooltipSnapshot` и не имеет отдельного switch.

## ASM и упаковка

Agent и bootstrap компилируются `javac --release 17`. Build dependencies зафиксированы как ASM
9.10.1 (`asm`, `asm-tree`, `asm-analysis`, build-only `asm-commons`, test-only `asm-util`) с SHA-256
в `lib/ASM-SHA256SUMS.txt`. Build-only relocator перемещает runtime ASM в
`com.starsector.prepatcher.internal.asm`. Agent JAR содержит `META-INF/LICENSES/ASM.txt`, но не
содержит public/JDK-internal ASM paths, чужих manifests, signatures или `module-info.class`.
Faster Rendering и файлы `Java28PrepatcherCompat.zip` в дистрибутив не входят.

## Установка и Miko

Installer проверяет layout файлов: читаемый `fr.agent.jar` с `Premain-Class` даёт порядок
`остальные agents → fr.agent.jar → Prepatcher → classpath`; иначе наличие legacy
`AppClassLoader`/`ClassTransformer` сохраняет system-loader argument. Runtime всё равно принимает
решение только по живой пробе. `Miko_Simple.txt`, `mikohime/DefaultVM`, `Configure_Me.cmd` и
`Miko_Rouge.bat` обновляются одной транзакцией с timestamped backups и rollback. Generator больше
не восстанавливает `spp.dump.campaignState`; launcher сохраняет `%ERRORLEVEL%`, делает `pause`
только при ошибке и возвращает этот code через `exit /b`.

AoTD marker discovery теперь открывает только JAR paths из `mod_info.json`. Diagnostic `.build` и
archive copies не создают ложный `AMBIGUOUS`.

## Owned AoTD fork

Scheduler Fork `1.0.14-spp13` остаётся first-class implementation. Bridge schema V10 и public
Prepatcher/AoTD ABI не изменены. Реальные fork surfaces по-прежнему проверяются existing exact-JAR
gates; Local Resources fork наследует безопасный путь или использует уже поддерживаемый fork-owned
snapshot helper. Future critical override fixture остаётся fail-closed.

## Выполненная валидация

- `verify-structural.ps1` и `verify-structural.sh` завершены с кодом 0:
  structural/runtime/AoTD exact-fork, future-override, idempotency, atomic rollback, startup и
  Java 17/27 legacy-FR gates прошли;
- обе release JAR собираются через PowerShell и shell scripts на Java 17 после ASM relocation;
  повторные сборки и оба scripts дали одинаковый agent SHA-256;
- agent содержит 94 private ASM entries и лицензию; public/JDK-internal ASM, `module-info.class`,
  чужие manifests и signatures отсутствуют;
- Java `27+22` без FR: выбран `JAVA27_STANDARD`, все 24 presentation targets и Local Resources
  загружены с `-Xverify:all` через обычный pipeline;
- в текущей установке реального `starsector-core/fr.agent.jar` нет, поэтому subprocess-smoke
  `FR_AGENT_CHAIN` честно отмечен `SKIPPED`; маршрут проверен на уже нормализованных байтах Trade и
  Market Overview через полный pipeline, а при появлении файла оба verification scripts
  автоматически запустят Java 27 smoke с порядком `fr.agent.jar -> Prepatcher`;
- Java `27+22`, старый реальный `fr.jar` и system `AppClassLoader`: выбран
  `FR_PREDEFINE_BRIDGE`, live `Global.class` handshake прошёл, встроенный illegal-name repair
  позволил загрузить те же 24 presentation targets, Local Resources прошёл с `-Xverify:all`;
- legacy bridge прошёл оба setup-пути: ещё не загруженный `ClassTransformer` и предварительно
  загруженный класс через retransformation;
- Java `27+22` без FR и с legacy bridge загрузила оба проблемных UI-класса с `-Xverify:all`:
  `tradeMarketMutationPatch`, `marketOverviewMutationPatch` и
  `campaignCargoNoGlobalEconomyStepPatch` получили `APPLIED`, соответствующих `pipelineFailure`,
  `ClassFormatError` и `VerifyError` нет;
- отдельная четырёхмаршрутная проверка подтвердила raw/repaired имена, порядок Trade -> Cargo,
  идемпотентность и атомарный откат всего класса при намеренно сломанном позднем Cargo matcher;
- Java 17 со старым реальным FR: выбран `JAVA17_STANDARD`;
- все четыре отрицательных Java 27 cases (FR заявлен, но ничего не меняет; стоит после Prepatcher;
  меняет только declaration; повреждает body) завершили JVM в `premain` до runtime installation;
- на изолированных копиях Miko оба FR layouts прошли install/reinstall/uninstall: повторная
  установка байт-в-байт идемпотентна, порядок и trailing newline сохранены, launcher возвращает
  настоящий `%ERRORLEVEL%`.

Raw output хранится только в `.build/reports/`. Финальный игровой процесс не завершается
автоматизацией: пользователь завершает его сам либо ждёт естественного окончания, а проверка лишь
читает log. Ручной запуск `Miko_Rouge.bat` остаётся последним acceptance gate и в этой автоматической
матрице не выполнялся.

## Остаточный риск

Совместимость с JVM новее 27 не заявлена. Новый FR сам печатает checksum игрового JAR, но
Prepatcher не использует это значение при выборе маршрута. Полный запуск конкретного modpack
остаётся обязательным ручным acceptance gate: меню или устойчивое ожидание без
`ClassFormatError`, `VerifyError`, ASM `NoClassDefFoundError` и
`Unsupported class file major version 71`.
