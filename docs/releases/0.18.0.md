# Отчёт о выпуске 0.18.0

Дата выпуска: 2026-08-10

Поддерживаемая игра: Starsector 0.98a-RC8

Поддерживаемый AoTD Scheduler Fork: `1.0.14-spp10`

## Что исправлено

Во время сохранения Starsector временно удаляет внутренние supply/demand maps всех industries, а
затем восстанавливает industries по одной. AoTD population industry могла в своём restore callback
создать товары и немедленно запросить данные у следующей industry, чьи maps ещё не были
восстановлены. Старый upstream-код молча прекращал такой refresh; scheduler rewrite превращал это
ожидаемое временное состояние в тысячи исключений и ERROR-сообщений.

`0.18.0` разделяет две операции:

- restore callback создаёт или конвертирует только commodity-структуру;
- расчёт supply/demand начинается после полного vanilla restore barrier и выполняется обычным
  scheduler pipeline один раз для каждого затронутого рынка.

Это сохраняет атомарную публикацию полной рыночной revision, но убирает расчёты, исключения и
массовую запись в лог из чувствительного save/load lifecycle.

## Exact CoreLifecycle hook

Переключатель `patch.aotdEconomyRestoreCoordination=true` добавляет один независимый transformer для
точного метода `CoreLifecyclePluginImpl.econPostSaveRestore()V`. Structural contract требует:

- concrete `public static` метод;
- ровно один `Industry.doPostSaveRestore()`;
- ровно по одному `MarketAPI.reapplyConditions()` и `reapplyIndustries()` после него;
- исходный порядок двух полных проходов, финальный iterator tail и единственный успешный `RETURN`;
- отсутствие новых exception regions и видимость typed runtime из loader target-класса.

Hook `publishAoTDEconomyRestoreComplete()` вставляется непосредственно перед этим `RETURN`. В
игровом core он выполняет O(1) работу: берёт один loader-local `Runnable` и вызывает его. Ни рынок,
ни industry, ни commodity там не перечисляются.

Structural mismatch оставляет оригинальный classfile и не объявляет restore capability, а
отсутствующий V10 listener отклоняет весь обязательный handshake с mask `0`. Callback failure
никогда не выходит в Starsector lifecycle. После успешной регистрации только `LinkageError`
удаляет restore capability; остальные ошибки остаются retryable, учитываются отдельным счётчиком и
логируются ограниченно — первые четыре раза и далее на степенях двойки.

## Bridge V10

Текущий контракт поддерживается только как точная пара:

- Prepatcher `0.18.0`;
- Scheduler Fork `1.0.14-spp10`;
- bridge schema V10;
- required capability mask `0xbff`;
- declared/full mask `0xfff`.

Новая единая capability `ECONOMY_RESTORE_COORDINATION` занимает bit 11. Bit 10 остаётся optional
`UI_MARKET_MUTATION_REFRESH`; поэтому все поставляемые профили согласуют `0xbff`, а профили с
`patch.uiMarketMutationRefresh=true` — `0xfff`. V10 требует три loader-local callbacks: delivery
listener, deficit resolver и economy-restore `Runnable`. Старые `spp4`–`spp9`, future identifiers,
неполная mask или отсутствующий callback отклоняются целиком.

## Поведение Scheduler Fork

Restore-time commodity path больше не запускает industry-derived calculation. После completion
signal форк объединяет повторные отметки рынка и оставляет один normal scheduler refresh. Полная
следующая supply/demand revision сначала готовится во staging buffers и публикуется только целиком;
неудачная подготовка не меняет предыдущую committed revision.

Получение `industry.getDemand()/getSupply()/getQuantity()` отделено от calculation scripts. Только
эта snapshot stage может вернуть `NOT_READY`. Такой результат:

- не создаёт exception и не пишет ERROR;
- не продвигает authoritative или committed dirty generation;
- не очищает предыдущие maps/scalars;
- не считается failure и не приводит к quarantine;
- остаётся dirty до полного restore signal и следующего scheduler pass.

Calculation scripts вызываются после успешного полного snapshot. Их `RuntimeException` остаётся
настоящей видимой ошибкой: release не маскирует ошибки формул или сторонних commodity scripts.

## Сохранения и производительность

Per-industry supply/demand maps в `AoTDSupplyDemandData` являются derived cache. Раньше они могли
удерживать `MutableStat` из industry maps даже после vanilla pre-save cleanup, увеличивать save graph
и восстанавливаться как detached старые значения. Новые saves не содержат их entries и ссылок на
industry `MutableStat`; пустые runtime buffers нормализуются после загрузки и перестраиваются из
актуальных industries за restore barrier. Постоянные gameplay modifiers и aggregate-значения
товара сохраняются.

Основной lifecycle path теперь имеет следующую стоимость:

- O(1) в transformed CoreLifecycle method;
- один coalesced dirty event на затронутый рынок в fork;
- один штатный market-wide prepare/commit вместо commodity-by-industry exception storm.

В этом выпуске serialization change ограничено содержимым per-industry cache в
`AoTDSupplyDemandData`. Оно не заявляет изменений сериализации scheduler registry, очередей, epochs,
worker futures или DTO.

## Совместимость сохранений

Автоматическая migration fixture использует реальный класс форка и поставляемый Starsector
XStream 1.4.10. Она загружает фиксированный spp9 XML с непустыми derived maps, общей ссылкой на один
`MutableStat`, aggregate-значениями и временным gameplay modifier. Проверяются:

- сохранность supply/demand/available aggregates и gameplay modifier с оставшимся временем;
- удаление старых detached cache entries и нормализация пустых runtime buffers без обращения к
  industries;
- новое сохранение без per-industry cache contents/references и его повторная загрузка;
- сохранность shared-reference alias у persistent stat через `writeReplace()`/`readResolve()`.

Prepatcher не меняет общий формат сохранений Starsector. Миграция касается только owned state
Scheduler Fork. Автоматический gate проверяет точную библиотеку serializer и реальный класс форка,
но не заменяет полный campaign save: обычный load, успешный save, failed save и фактический порядок
callbacks остаются ручной проверкой.

## Проверка выпуска

Release gate включает:

- real RC8 CoreLifecycle structural transform, idempotency и ASM verification;
- changed-order, changed-call-count, changed-tail и exception-region negative fixtures;
- disabled config, missing callback, throwing callback и `LinkageError` fail-open tests;
- точную V10 registration matrix для `0xbff`/`0xfff` и отказ V9/future/partial contracts;
- real `AoTDToolboxTheory.jar` `1.0.14-spp10` и проверку parent-runtime/child-mod loader topology;
- real-fork structural gate линейного industry snapshot без повторных `Market.getIndustry(id)`;
- actual-fork/XStream 1.4.10 migration фиксированного spp9 XML и spp10 round-trip;
- documentation consistency, actual-javaagent и Faster Rendering smoke.

Полный campaign smoke с реальным сохранением остаётся обязательной ручной проверкой перед
публикацией архива. Он должен отдельно пройти population-first restore, transient `NOT_READY`, один
coalesced refresh, видимую ошибку calculation script, успешный save и failed-save recovery. Raw
verifier output принадлежит `.build/reports/` и не копируется в tracked release documentation.

## Обновление

Prepatcher `0.18.0` и Scheduler Fork `1.0.14-spp10` следует обновлять одновременно. Не нужно
устанавливать изменённый `starfarer.api.jar`: runtime bridge поставляется javaagent-ом. После замены
файлов следует повторно запустить installer, чтобы Prepatcher оставался последним managed
`-javaagent` в vanilla и/или Faster Rendering launch configuration.
