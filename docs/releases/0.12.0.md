# Отчёт о выпуске 0.12.0

Дата: 2026-07-26.

## Назначение

`0.12.0` устраняет повторный полный обход всех звёздных систем из core-worlds hot path,
добавляет инкрементальный destination index для `StrategicModule` и переводит вычисление market
share на линейные и invocation-local пути. Выпуск сохраняет compatibility-first модель: каждый
новый путь включается только после полного structural proof, а неподтверждённая реализация
продолжает использовать сохранённое raw/vanilla-поведение.

Если установлен **AoTD — Theory of Toolbox**, для оптимальной производительности требуется
поддерживаемый Scheduler Fork `1.0.14-spp1` или новее. Без AoTD форк не нужен. Исходная сборка AoTD
может работать через fail-closed/raw пути, но не предоставляет полный поддерживаемый native
scheduler contract Prepatcher.

## Incremental core-worlds extent index

### Причина

Предыдущая реализация `patch.coreWorldsExtentCache` подавляла лишние публикации трёх `Vector2f`, но
при каждой проверке вызывала `SectorAPI.getStarSystems()`. `CampaignEngine` возвращает defensive
`ArrayList`, поэтому с примерно 2559 системами hot path продолжал выполнять Θ(S)-обход и создавать
Θ(S)-reference snapshot.

### Transformation surface и композиция

Исправление представляет один fail-closed контракт трёх vanilla-классов:

1. `CoreScript.advance(F)V`: единственный terminal-вызов `Misc.computeCoreWorldsExtent()` после
   `RouteManager.advance(F)V` заменяется вызовом runtime index;
2. `CampaignEngine.createStarSystem(String)` и
   `removeStarSystem(StarSystemAPI)`: epilogue-hooks публикуют успешные мутации authoritative
   system list;
3. `BaseLocation.addTag(String)`, `removeTag(String)` и `clearTags()`: hooks на всех normal exits
   публикуют изменения core-tag membership.

Для каждого surface проверяются data flow исходной мутации, multiplicity, owner marker,
idempotent postcondition и ASM verification. Incremental runtime активируется только когда оба
mutation-owner класса имеют статус `APPLIED` или `ALREADY_APPLIED`. Partial match, foreign hook или
изменившийся surface оставляет `CoreScript` на сохранённом vanilla computation; частично
инвалидируемый индекс не используется.

Эти методы не пересекаются с другими включёнными patch surfaces. Три участника применяются как один
capability group: поздняя загрузка любого mutation owner обновляет общий capability state, а
повторная обработка полностью преобразованного набора подтверждает совместный post-state.

### Runtime и сложность

Первый update новой campaign identity получает один authoritative snapshot и строит weak indexes
всех систем и subset с `theme_core`. Обычные create/remove/tag API mutations обновляют их событиями.
Каждая последующая проверка читает координаты C известных core systems и не более B элементов
rotating membership audit:

```text
steady-state work = O(C + B)
coreWorlds.auditSystemsPerFrame = 64
```

Прямое удаление `theme_core` из live tag set обнаруживается в текущем O(C)-проходе. Прямое добавление
в обход `addTag()` обнаруживается не позднее полного bounded audit cycle — при S=2559 и B=64 это
максимум 40 validated outer frames. API-mutations видны немедленно. Mutable coordinates остаются
видимыми в каждой выбранной validation iteration.

Origin-inclusive `+0.0f` arithmetic, порядок публикации min/max/center, fresh mutable vectors при
реальном изменении и repair удалённых, заменённых, изменённых либо истёкших memory values сохранены.
Lifecycle reset заменяет wrapper containers и не удерживает их старую backing capacity. Static state
содержит только weak campaign/system/vector references и не создаёт strong root на game или mod
classloader.

Owned AoTD fork не содержит зависимости, subclass или override owner для `CoreScript`,
`CampaignEngine` и `BaseLocation`. Поэтому fork support здесь намеренно не требуется: все три
surface остаются vanilla-owned и преобразуются напрямую.

## StrategicModule destination index

`StrategicModule` получил location-agnostic incremental index по destination `LocationAPI`.
Cold build, replacement, point refresh и continuous audit разбиты на bounded operations под единым
wall-clock/work-unit budget. Lookup не выполняет синхронный полный scan; пока snapshot не готов,
существующий истёкший `JumpPlan` сохраняется, а новый rebuild откладывается.

Полный call budget теперь включает lock, selection, queues, LRU и cleanup. Retry scan заменён
indexed min-heap, audit — O(1) round-robin queue; capacity pressure не вытесняет незавершённые
builds. Hooks `JumpPoint`, `JumpDestination` и `BaseLocation`, negative-result cache, failure
cooldown, bounded LRU, campaign-generation reset и weak-owner accelerator не создают
weak-key/value retention cycle.

## Market-share path

`CommodityMarketData.getMarketShareData()` агрегирует данные линейно и не выполняет повторный
`LinkedHashMap.put()` для уже материализованной записи. Player-owned identity semantics и raw
fallback сохранены. Vanilla и Nexerelin callers используют invocation-local identity cache с
независимыми switches:

```properties
patch.punitivePlayerShareLocalCache=true
patch.nexPunitivePlayerShareLocalCache=true
```

Optional Nex target не создаёт hard dependency. Ни один новый путь не добавляет campaign-lifetime
cache, instance field или `ThreadLocal`.

Для owned `AoTDCommodityMarketData` loader-safe `ClassValue` разрешает inherited optimization,
только пока пять critical methods остаются у vanilla owner. Regression запускается на реальном
`AoTDToolboxTheory.jar`; synthetic future override локально возвращается к raw behavior, а GC test
подтверждает отсутствие удержания disposable mod classloader.

## AoTD Scheduler Fork

Первый публичный пакет Scheduler Fork имеет label `1.0.14-spp1`; числовая runtime-версия мода
остаётся `1.0.14` для совместимости с version parser Starsector. Форк требует Prepatcher `0.12.0`,
активный javaagent, полный production capability mask `0x1ff` и оригинальный
`starsector-core/starfarer.api.jar`.

Native scheduler bridge, campaign/economy epochs, capability refresh и generation
resynchronization остаются непосредственно поддерживаемыми surfaces. Устаревшую замену core JAR
устанавливать нельзя.

## Проверка выпуска

Полный release gate на референсной Windows-установке включает:

- documentation/version/link/checksum consistency;
- полный enabled order и idempotent reprocessing для structural patches;
- positive, unrelated-layout, partial, duplicate и foreign-hook fixtures;
- actual-agent core-worlds status `APPLIED/APPLIED/APPLIED`;
- один initial snapshot и отсутствие steady-state `getStarSystems()` calls;
- O(C+B), topology/tag events, direct tag mutations, recovery и weak-retention regressions;
- StrategicModule budget, queue, retry, lifecycle и GC regressions;
- vanilla, Nexerelin и real-owned-fork market-share tests;
- startup javaagent и реальный Faster Rendering classloader.

На 2026-07-26 gate завершён успешно: проверены 47 transformed classes и 2578 методов; все 111
target-loader runtime classes видимы через Faster Rendering loader.

## Остаточный runtime-check

Новая campaign telemetry должна подтвердить, что `SectorAPI.getStarSystems()` больше не появляется
регулярно под core-worlds runtime, а `coreWorldsSystemScans` остаётся равным одному после
инициализации, если не происходил recovery. Присутствие `computeAndPublish` допустимо: steady-state
проход ограничен core subset и bounded audit.

## Обновление

1. Полностью заменить каталог предыдущей версии.
2. Повторно запустить installer javaagent для используемых Vanilla/Faster Rendering launch paths.
3. При установленном AoTD заменить его на Scheduler Fork `1.0.14-spp1` или новее.
4. Сохранить оригинальный `starsector-core/starfarer.api.jar`.
5. Полностью перезапустить игру; javaagent не поддерживает горячее обновление.
