# Отчёт о выпуске 0.18.1

Дата выпуска: 2026-08-10

Поддерживаемая игра: Starsector 0.98a-RC8

Поддерживаемый AoTD Scheduler Fork: `1.0.14-spp11`

## Результат

Этот выпуск делает восстановление scheduler-состояния после загрузки предсказуемым без нового
вмешательства в загрузчик кампании Starsector. Prepatcher по-прежнему меняет только точный успешный
хвост `CoreLifecyclePluginImpl.econPostSaveRestore()V`. Форк использует этот сигнал для invalidation
derived economy state, а `onGameLoad(false)` — для привязки нового runtime epoch, нормализации
checkpoint незавершённой итерации и снятия load guard.

Исполняемый список `ReachEconomyStepper.tasks` больше не считается сохраняемым состоянием. Он может
содержать частично выполненные task-объекты, worker DTO, boundary handles и ссылки на прежний process
epoch. При чтении сохранения такой граф отбрасывается без live market reads. Если итерация была в
состоянии `DOING_TASKS`, `onGameLoad(false)` не выполняет economy-задачи немедленно: он только
привязывает загруженную economy и открывает load guard. Безопасный оставшийся суффикс создаётся
лениво при следующем `nextFrame`/`advance`.

Для `MAIN_WORK` checkpoint различает четыре случая. `FULL` применяется, если ни один market commit
ещё не был предпринят. `PRICE_REMAINING` хранит в исходном порядке точные stable IDs только тех
рынков, чьи price/stockpile/month commits ещё не пытались выполнить; transient global commodity
data при этом заново строится по полному набору рынков, а затем публикуется только оставшийся
per-market суффикс. `LISTENERS_ONLY` выполняет единственную ещё не пройденную listener boundary после
всех market commits. Старый checkpoint без доказуемого плана получает `DROP`. Поэтому уже
предпринятые commits не повторяются, а оставшаяся месячная работа не теряется.
`UPDATE_MARKETS` и `IMMIGRATION` продолжаются только для точно сохранённых оставшихся market IDs,
поэтому population уже обработанных рынков не применяется повторно; незавершённый
`POST_IMMIGRATION` полностью переснимает атомарный snapshot; `FINISH` создаётся заново. Календарные
поля, число оставшихся итераций и month-end intent сохраняются.

При обычном сохранении detached-граф временно удерживается только для освобождения ресурсов и не
возвращается в stepper даже после успешного save. Успешный и неуспешный callbacks используют один
semantic resume: в обратном порядке закрываются `FINISH` boundary, очищается подготовленный `POST`,
затем отменяются MAIN futures и возвращается dirty work незавершённых tickets. Суффикс остаётся в
checkpoint и лениво пересоздаётся уже из актуальных post-save данных. Вложенные suspend/resume не
очищают граф раньше внешней пары; состояние `WAITING` или отсутствие checkpoint приводит к простому
discard и завершению baseline, без ложного restart.

Ранние штатные economy steps больше не тратят время на серию commits, которые гарантированно вернут
`UNKNOWN_MARKET`, пока loader-local registry ещё пуст. Post-immigration snapshot делает один bulk
check lifecycle и откладывает registry publication до полного rebuild. Когда registry уже `READY`,
trade capture повторно использует только revision с точно совпавшим dedicated
materialized-input generation и pre-immigration market-size checkpoint. Обычные trade,
accessibility и faction changes этот generation не меняют. При несовпадении proof весь рынок
рассчитывается одним live path, без смешивания двух revisions; даже при неизменившихся trade values
ставится один coalesced materialized repair, чтобы следующий scheduler pass восстановил fast path.

Так как post-immigration capture может занимать несколько кадров, каждый подготовленный рынок несёт
точный loader-local proof: identity/token registry, size, faction, accessibility и наличие
spaceport. Непосредственно перед публикацией устаревшие рынки выборочно переснимаются, затем весь
набор proof проверяется под lock registry и trade manager публикует либо полный cut, либо ничего.
Остаточная гонка возвращает `STALE_INPUT` и сохраняет dirty work. Если сама публикация выбрасывает
`RuntimeException`, manager откатывается к предыдущему полному cut, а task гарантированно
завершается; ошибка последующего registry bookkeeping консервативно возвращает незавершённую работу
в scheduler.

`AoTDUpdateMarketAgainTask` больше не обходит industries для чистого price, stockpile,
accessibility или trade debt: этот этап выполняется только при наличии materialized work. Чтобы это
ускорение не пропустило обязательный месячный пересчёт, month-end AoTD mutation явно invalidates
`VALUE + DERIVED + PRICE + STOCK` до запуска обычного pipeline.

## Почему не добавлен CampaignGameManager hook

Read-only аудит реального `starfarer_obf.jar` 0.98a-RC8 подтвердил порядок успешной загрузки:

1. `CoreLifecyclePluginImpl.econPostSaveRestore()`;
2. `Economy.tripleStep()`;
3. все `ModPlugin.onGameLoad(false)`;
4. второй `econPostSaveRestore()`;
5. второй `tripleStep()`;
6. `CampaignEngine.advance(0)`;
7. финальный `EconomyAPI.doubleStep()`;
8. сброс `Global.LOADING_SAVE` и единственный успешный return.

То есть Starsector намеренно выполняет `3 + 3 + 2` полных economy steps. Нормализация checkpoint,
привязка epoch и снятие load guard выполняются до `advance(0)`, но задачи безопасного суффикса
создаются только лениво при следующем вызове stepper. Transient restore markers потребляются до
registry rebuild. Для этого уже достаточно существующего V10 callback и штатного
plugin lifecycle. Дополнительные begin/end hooks расширили бы ABI и новый transformation surface,
но не устранили бы дополнительную корректностную проблему. Поэтому исходные восемь economy steps и
весь `CampaignGameManager` оставлены без изменений.

## Контракт и совместимость

Поддерживается только точная пара:

- Prepatcher `0.18.1`;
- Scheduler Fork `1.0.14-spp11`;
- bridge schema V10;
- required capability mask `0xbff`;
- declared/full mask `0xfff`.

Descriptors, три loader-local callbacks и capability composition не изменились. Версия fork
повышена из-за нового обязательного поведения сохранения/восстановления, а не из-за нового bridge
payload. `spp10`, более старые и будущие identifiers, другая mask или другая V10 shape отклоняются
целиком. Это не позволяет Prepatcher объявить production profile активным для fork, который ещё
может возобновить process-local task graph из сохранения.

Ранний filesystem scan остаётся только диагностикой. Он не открывает JAR-копии в деревьях с path
segment, начинающимся с `.`, включая `.build`, и в `releases`; поэтому compiler/audit/staging
артефакты не создают ложный `AMBIGUOUS`, а официальный `jars/` остаётся единственным кандидатом.
Capability state по-прежнему активирует только runtime handshake реально загруженного fork.

## Transformation surfaces и композиция

Новых transformers нет. Сохраняется surface выпуска 0.18.0:

- target: `com/fs/starfarer/api/impl/campaign/CoreLifecyclePluginImpl`;
- method: `econPostSaveRestore()V`;
- region: единственный успешный tail после industry `doPostSaveRestore`, затем полных market
  `reapplyConditions` и `reapplyIndustries` passes;
- injected call: loader-neutral `publishAoTDEconomyRestoreComplete()` непосредственно перед
  единственным `RETURN`.

Strict fork-version acceptance меняется только в runtime contract и его тестах. Она не пересекается
с bytecode surfaces других patches. Structural failure CoreLifecycle по-прежнему не публикует bit
11; `LinkageError` callback снимает только restore capability, а обычный callback failure остаётся
ограниченно логируемым и не выходит в Starsector lifecycle.

## Проверки выпуска

Автоматические gates должны подтвердить:

- точное принятие только `1.0.14-spp11` при V10 и masks `0xbff`/`0xfff`, включая явный отказ
  `spp10`;
- marker discovery с официальным `jars/` и дубликатами под `.build`/`releases`, подтверждающий
  отсутствие ложного `AMBIGUOUS` до runtime handshake;
- неизменность real RC8 CoreLifecycle transform, idempotency, drift rejection и ASM verification;
- real-fork bytecode contract для XStream task sanitization, load guard и checkpoint bind из
  `onGameLoad(false)`;
- XStream 1.4.10 round-trip с удалением runtime task graph, сохранением calendar/iteration state и
  четырьмя MAIN checkpoint modes: полный restart до первого commit, точный unattempted market
  suffix после него, listener-only tail и безопасный legacy drop; global commodity data обязана
  перестраиваться по полному market scope;
- одинаковый semantic resume после успешного и неуспешного save: без возврата live graph, с отменой
  futures, возвратом ticket debt, очисткой POST/FINISH ресурсов, однократной внешней обработкой
  nested save и discard без checkpoint в `WAITING`;
- один EMPTY-registry bulk deferral вместо per-market `UNKNOWN_MARKET` commit pass;
- authoritative trade-net fast path только при совпавшем dedicated materialized-input generation и
  точном pre-immigration market-size checkpoint; trade/accessibility/faction changes не меняют этот
  token, а рост vanilla market size при неизменных trade values обязан включить полный live fallback
  и поставить ровно один coalesced materialized repair;
- multi-frame scalar/token proof, выборочный stale recapture и единая registry-locked публикация;
  residual `STALE_INPUT` сохраняет dirty work, publication failure откатывает полный cut и не
  оставляет post-task навсегда активным;
- отсутствие industry traversal в `AoTDUpdateMarketAgainTask` для чистого non-materialized debt и
  явная month-end materialized invalidation перед обязательным месячным pipeline;
- сохранение исходных двух `tripleStep`, одного `doubleStep` и всех восьми economy iterations в
  реальном `CampaignGameManager` bytecode.

После сборки рекомендуется отдельная acceptance-проверка на пользовательском сохранении:
population-first restore, загрузка с незавершённой monthly iteration, успешный и неуспешный save,
отсутствие NPE storm и повторного применения старого task graph. Это не автоматизированный release
gate; данный отчёт не утверждает, что такой интерактивный прогон выполнен.

## Обновление

Prepatcher `0.18.1` и Scheduler Fork `1.0.14-spp11` следует обновлять одновременно. Изменённый
`starfarer.api.jar` не нужен. После замены файлов следует повторно запустить installer, чтобы
Prepatcher оставался последним managed `-javaagent` в используемой launch configuration.
