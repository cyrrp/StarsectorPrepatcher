# Отчёт о выпуске 0.17.0

Дата: 2026-07-29
Поддерживаемая игра: Starsector 0.98a-RC8

## Область выпуска

Выпуск включает exact vanilla industry mutations в единый affected-commodity/local refresh
pipeline и исправляет границу с AoTD. Scheduler Bridge schema остаётся V9, а поддерживаемый
Scheduler Fork обновлён до `1.0.14-spp7` с одним explicit UI economy dispatcher.

Пользовательская возможность и конфигурация атомарны: `patch.uiMarketMutationRefresh` включает
определение точной UI-мутации, внутренний one-shot setter/helper context для non-trade paths,
прямой trade guard, локальный refresh и перестроение затронутых commodity. Bytecode-преобразования остаются отдельными только у
непересекающихся surfaces:
market overview `reapplyConditions`, trade transaction, industry dialog/panel и конструктор
`CommodityMarketData`. Названия этапов разработки и отдельные capability-биты для частей этой
цепочки удалены.

## Стандартные шаги и explicit UI dispatch

В spp7 стандартный контракт восстановлен без эвристик: `AoTDEconomy.nextStep(EconWorkParams)`,
`doubleStep()`, `tripleStep()` и `AoTDReachEconomy.nextStep(EconWorkParams)` всегда выполняют полный
all-market pipeline. `doubleStep()` и `tripleStep()` сохраняют vanilla-кратность в два и три
глобальных шага. Пустой payload и `currentlyOpenMarket` больше не меняют их область.

Prepatcher классифицирует только доказанные call sites и вызывает один public final
`AoTDEconomy.dispatchPrepatcherUiEconomyStep(int, MarketAPI, long, String[])` с intent
market-open, Cargo или market-mutation. Transformation surfaces для открытия рынка и Cargo — это
guards непосредственно вокруг исходных virtual `Economy.nextStep()`/`tripleStep()` в
`CampaignEngine.reportPlayerOpenedMarket(MarketAPI)` и точной `fake_market` ветке Cargo panel.
Runtime ownership определяется по loader-local callbacks, зарегистрированным проверенным Scheduler
Bridge V9. Это исправляет реальную топологию Starsector, где runtime bridge загружен родительским
loader, а `AoTDEconomy` — дочерним; одноимённый класс из незарегистрированного loader по-прежнему
fail-closed.
Trade `confirmTransaction()V` аналогично получает boolean guard вокруг сохранённого
`EconomyAPI.doubleStep()V`; affected IDs читаются прямо из transaction, без ThreadLocal
record/consume round trip. Оборачивания всего метода и публикации opening/detached-Cargo/trade
context больше нет.

## Nexerelin: военные действия

Военный dialog через Starship Legends вызывает виртуальный `MarketCMD.showDefenses()`, который в
Nexerelin 0.12.1d переопределён собственным `Nex_MarketCMD.showDefenses(Z)V`. Поэтому прежняя
vanilla-трансформация применялась, но runtime dispatch обходил её и выполнял Nex-копию
`Global.getSector() → getEconomy() → tripleStep()`, запуская полный AoTD all-market pipeline.

`patch.marketDefensesNoGlobalEconomyStep` теперь прямо поддерживает эту отдельную поверхность по
реальному `ExerelinCore.jar`. Matcher доказывает exact superclass, protected descriptor,
единственный class-local step, owner-local захват interaction fleet/station fleet/station state до
шага и точный market-null join. Удаляется только stack-neutral тройка вызовов; invasion/responder,
dialog и локальные defense calculations Nex остаются неизменными. Класс преобразуется в дочернем
mod loader без runtime helper или сохранения loader, а JAR на диске не изменяется. Future superclass,
изменённый control flow, bootstrap или unrelated-loader copy получают локальный fail-closed fallback.

Исходный virtual call остаётся в каждом transformed method и является единственным владельцем
fallback. Runtime guard никогда не вызывает его сам: при `false`/exception dispatcher,
`GLOBAL_TOPOLOGY`, отсутствии capability или подтверждённого debt barrier, неизвестной ревизии
форка и structural drift управление доходит до исходной инструкции. Поэтому fallback всегда
действительно глобальный, а не повторно локализованный стандартным методом AoTD.

Поддерживается один текущий контракт: bridge schema V9, точная версия `1.0.14-spp7` и точная
declared mask `0x7ff`. spp4-spp6, будущие версии и частично объявленные контракты логируются и
целиком отклоняются с negotiated mask `0`; отдельных legacy-веток исполнения больше нет.

Обязательный `UI_ECONOMY_DISPATCH` не зависит от optional optimization switches. Поэтому exact
spp7 получает required mask `0x3ff` даже в safe profile; только включённый
`patch.uiMarketMutationRefresh` добавляет optional bit и даёт полный `0x7ff`.

## Активные industry branches

Transformer патчит только пять доказанных call sites в `IndustryConfigDialog.dialogDismissed()`:

- `Industry.startUpgrading()`;
- `Industry.downgrade()`;
- два vanilla `MarketAPI.removeIndustry(...)` пути;
- `Industry.cancelUpgrade()`.

Перед мутацией доставляется накопленный scheduler debt конкретного рынка. После мутации выполняется
reapply conditions/industries и before/after diff локального commodity vector. Если изменились
commodity IDs, выполняется targeted commit: локальный refresh рынка плюс global/econ-group
`CommodityMarketData` rebuild только для этих IDs. Если commodity vector не изменился, используется
локальный industry/state refresh без global commodity rebuild.

Вся оптимизационная подготовка теперь best-effort: transaction/cargo/stack reads, market/economy
proofs, free-port/industry snapshots, публикация context, счётчики и логирование находятся внутри
fail-open границы. Исходный setter или industry mutator выполняется ровно один раз вне этой границы,
поэтому его собственное исключение не поглощается. Ошибка pre/post snapshot монотонно отравляет
текущий setter batch; последующая успешная mutation не может стереть неопределённость, и shared
helper выполняет сохранённый global `tripleStep()`.

`IndustryListPanel.recreateOverview()` сохраняет исходный `tripleStep()` и пропускает его только при
валидном one-shot context того же рынка. Поэтому семь общих callers не становятся неявно
оптимизированными: custom `IndustryOptionProvider`, construction queue, build picker и неизвестные
modded actions продолжают штатный global fallback.

Dialog и panel образуют одну атомарную patch group: runtime-путь включается только после успешной
проверки обоих targets. Structural drift любого участника отключает всю группу, поэтому частично
преобразованный dialog не может подавить исходный panel `tripleStep()`. AoTD materialization tasks
в этом пути не рассылают общий список commodity callbacks; отсортированный affected set публикуется
ровно один раз после окончательного локального commit.

## Fail-closed границы

Оригинальный `tripleStep()` сохраняется при любом из условий:

- exact bytecode inventory dialog или overview helper изменился;
- pre-mutation debt barrier завершился ошибкой;
- economy/market не соответствуют доказанному vanilla или согласованному AoTD contract;
- one-shot market identity, thread или campaign/economy epoch не совпали;
- final vanilla affected-commodity contract недоступен;
- mutation пришла из custom/unknown caller без exact wrapper;
- explicit spp7 dispatcher отклонил action или завершился ошибкой.

Administrator assignment в этом выпуске не локализуется. Vanilla может за одну UI-транзакцию
изменить администратора сразу у нескольких player markets; single-market schema V9 не может
корректно выразить такой commit. Этот путь остаётся глобальным до отдельного multi-market contract.

## Принятые остаточные риски

Semantic gate для final vanilla `CommodityMarketData(String,String)` проверяет точные counts
ключевых вызовов, часть argument/field flow и отсутствие exception regions, но пока не доказывает
полный CFG, порядок commit-операций и receiver flow всех вызовов конструктора. Поэтому валидный
сторонний transformer теоретически может сохранить проверяемые anchors и одновременно изменить
семантику конструктора; такой совместимый по текущему matcher класс может получить `READY`, после
чего targeted affected-commodity commit вправе пропустить исходный global step. Поставляемый
`Starsector 0.98a-RC8` target проверен, поэтому риск относится к совместной работе с другими
bytecode-transformers или будущим structurally similar target. До усиления gate полный fail-closed
режим для этого пути обеспечивается отключением `patch.uiMarketMutationRefresh`.

## Проверка

Выпуск добавляет exact ASM gates для vanilla targets, проверку пяти wrapper calls, сохранение всех
семи shared-helper callers, idempotency, future-bytecode negative fixture и BasicVerifier для
transformed methods. Market-open/Cargo/trade postconditions требуют ровно один guard и сохранённый
original virtual call при нуле opening/detached/trade context hooks. Для общего trade/Cargo класса
проверяется фактический порядок `TradeMarketMutationTransformer → AoTDDetachedCargoContextTransformer`,
combined final postconditions, повторная обработка и сохранение раннего trade patch при отказе
позднего Cargo matcher.

Owned-fork support реализован прямо в spp7 source и проверяется по реальному
`AoTDToolboxTheory.jar`: четыре стандартных step method остаются global, public dispatcher — final,
его три intent имеют отдельные contract paths, а стандартные методы не читают
`currentlyOpenMarket` и legacy context consumers. Future-version/override fixture не получает
dispatch capability и исполняет сохранённый global call.

Исходный пакет прошёл полный Linux structural/runtime gate с реальным AoTD fork. После интеграции
2026-08-03 дополнительно выполнен полный Windows PowerShell gate на Microsoft OpenJDK 17.0.19:

- documentation consistency: version `0.17.0`, 27 Markdown-файлов, 82 относительные ссылки и
  71 patch scenarios;
- полный enabled order всех затронутых surfaces, combined postconditions, idempotency, rollback/fail-closed и
  future-bytecode negative fixtures;
- runtime guards/wrappers trade/free-port/industry, включая бросающие `getMarket`, bought/sold Cargo,
  `getStacksCopy`, stack getters, pre/post snapshots и logger; sticky poison, неизменные mutation
  exceptions, explicit market-open/Cargo/mutation dispatch, global-topology/barrier/capability/error
  fallbacks, parent-runtime/child-mod loader dispatch, foreign-loader rejection и real-fork spp7
  compatibility;
- реальный Nexerelin 0.12.1d `ExerelinCore.jar`: raw/patched call inventory, ASM BasicVerifier,
  idempotency, changed-branch/future-superclass fail-closed, child-mod loader actual-javaagent load и
  bootstrap/unrelated-loader rejection;
- lifecycle/GC, hyperspace, actual-javaagent startup, XStream save и реальный Faster Rendering
  loader smoke;
- `CacheMaintenanceRuntimeTest` отдельно прошёл `-Xint`, C1 (`TieredStopAtLevel=1`) и
  `-XX:-TieredCompilation`.

Windows/JDK 17 выявил platform-dependent инициализацию `MarketCMD.RaidDangerLevel` при создании
dynamic proxy для `Industry`. Fixture теперь устанавливает минимальный `Global` settings stub до
proxy generation; production surface не менялся.

## Упаковка

Agent/bootstrap и fork JAR собираются на Java 17. Совместимый архив имеет каноническое имя
`AoTD-Theory-Of-Toolbox-Scheduler-Fork-1.0.14-spp7.zip`; окончательные digests принадлежат
соответствующим `SHA256SUMS.txt` и проверяются по полному payload после финальной сборки.
