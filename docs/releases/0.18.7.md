# Отчёт о выпуске 0.18.7

## Итог и состав

Добавлена поддержка Starsector 0.98.5a-RC3 на Windows и Linux с сохранением 0.98a-RC8.
Внутренние имена переводятся вокруг полного ordered pipeline и runtime payload.
Канонический namespace остаётся Windows 0.98a-RC8; две новые таблицы содержат по 2841
доказанному соответствию классов. Выбор выполняется по фактическому descriptor
`CampaignEngine.advance`; неоднозначные соответствия не угадываются. Build создаёт
приватный canonical view, runtime возвращает native identity. Игровые JAR мод не заменяет.

Адаптированы следующие release-specific поверхности:

- `Memory.advance(F)V`: новая форма с отложенным удалением зависимых ключей; ранний выход
  разрешён только при пустых `expire` и `require`, остальная логика сохраняется.
- Загрузчик rules.csv: те же девять literal-parser sites переносятся в новую перегрузку,
  wrapper сохраняется. Новая форма текстового загрузчика сохраняет удаление начального BOM.
- `BaseTiledTerrain.render` / `isTileVisible`: согласованно проверяются старая и новая формы
  viewport height, вертикального сравнения и присваивания clamp по длине того же inner array.
- `ScriptStore$3.run()V`: отсутствие прежнего INFO cost доказывается как `NOT_NEEDED`.
- `DynamicParticleGroup.advance(F)V` после текущего FR: точная allocation-free array-compaction
  форма получает `NOT_NEEDED`; байткод, callbacks и порядок частиц FR сохраняются.

`NOT_NEEDED` не добавляет marker и не увеличивает счётчики применений/пропусков; отсутствие
стоимости повторно проверяется после последующих преобразований и в финальной композиции.
Число `patch.*`, defaults, invariants и порядок pipeline сохраняются. Текстовый загрузчик
и startup log aggregation остаются выключенными по умолчанию. Текущие контракты и точные
поверхности принадлежат [PATCHES](../PATCHES.md), loader/composition rules —
[COMPATIBILITY](../COMPATIBILITY.md).

## Загрузчики и поддерживаемый форк

Legacy FR predefine bridge больше не запускает трансформацию служебного класса агента:
собственная пара control loader/CodeSource исключается до открытия диагностической транзакции.
Чужие JAR и неизвестные CodeSource того же parent loader сохраняют обработку, включая
`sound.Sound`; package allowlist не вводится.

Construction-start ownership для AoTD сравнивает нормализованные file locations. Legacy FR
`file:/.../mod.jar!/` и URL с буквальными пробелами распознаются как тот же архив, с сохранением
existing escapes и знаков `+`. Другой архив, отдельная JAR entry, смешанные ABI resources
и parent shadowing не разрешают патч.

Scheduler Fork `1.0.14-spp13`, bridge V10, required mask `0xbff` и полный контракт `0xfff`
поддерживаются без нового выпуска форка. Локальные исходники и игровой JAR совпадают
с опубликованным spp13; последующие коммиты меняли документацию, упаковку и зависимость
Prepatcher `0.18.3 → 0.18.5`, отменив промежуточное `0.19.0`. Обе действующие зависимости
игра классифицирует относительно `0.18.7` как разрешающее запуск предупреждение
`MINOR_MISMATCH`. Runtime совместимость определяется bridge/ABI и capabilities.

Установщик оригинального Mikohime распознаёт объединённый агент/runtime в `fr.jar` по
Premain-Class и предпочитает его оставшемуся `fr.agent.jar`. Генератор и argfile получают
одинаковый выбор; Prepatcher остаётся последним javaagent. Gaius сохраняет владение
своей конфигурацией.

Финальный Windows player agent:
`dd56c05bb8a6414b1cfd99cc56c7ddcaee6d44c6d7df5a62ea86a2a715b79476`.

- Полные Windows `verify-structural.ps1` для обеих игр завершились с кодом 0: structural,
  runtime, negative/idempotency/composition, startup, hyperspace и optional-mod проверки,
  Java 17 и Miko `27+22`. На старой игре отдельно дополнены все доступные Nexerelin cases;
  на новой реальный Nexerelin включён в полный gate. Обе сборки дали одинаковый player JAR.
- Полные `verify-linux.sh` для обеих игр в изолированных Ubuntu VM каталогах завершились
  с кодом 0: canonical/native pipeline, shell/packaging fixtures, ShellCheck, Java `28-ea+13`
  и FR, DOM/SAX/XML, Preferences, реальный AoTD child-loader handshake `0xfff` и
  exactly-once restore. Для новой игры использован официальный FR 1.0.0.
- Точный Windows-built player agent с указанным SHA-256 отдельно прошёл на обеих Linux
  играх actual-agent route/core-worlds, все 138 payload и 73 native targets, XML/Preferences
  и AoTD. Linux/JDK-28 build не подменяет проверку поставляемого JAR.
- Новая Windows игра + FR 1.0.0 + Java 27 прошли native linkage всех 138/73 классов
  без pipeline rollback. Реальный particle override прошёл byte/counter preservation,
  idempotency, негативные варианты и final composition.
- Настоящий legacy FR ScriptClassLoader на Java 17 и 27 проверен с реальным spp13:
  construction-before-handshake, `0xfff`, native economy linkage и exactly-once restore.
  Raw/encoded URLs с пробелами, `+` и Unicode, foreign archive и JAR-entry negatives
  включены в construction ownership regression.
- `ControlPlaneIsolationTest` подтверждает исключение собственного control JAR до parsing
  и diagnostics и сохранение чужих/неизвестных источников того же loader.
- `GameUpdateBehaviorTest` исполняет реальные Memory bodies для empty/data/expiry/requirements/
  paused состояний и terrain bodies для квадратных, широких и высоких массивов и разных
  viewport. BOM/stream-error и differential literal-helper проверки прошли.
- Windows installer fixtures прошли merged/split/legacy FR, stale split agent, install/
  reinstall/regeneration/uninstall, backups, quoting, foreign agents/memory и Gaius matrix.
  Все installer fixtures выполнялись на изолированных копиях.
- Владелец подтвердил успешный полный игровой прогон с последними исправлениями на своей
  Windows-сборке 0.98a-RC8 и AoTD spp13. Все исполняемые `.class` финального JAR побайтно
  совпадают с прошедшим ручной прогон кандидатом; отличия — LF-нормализация двух namespace
  ресурсов и текста лицензии ASM.

Для ручного прогона восстановлены оригинальные `fs.common_obf.jar` и `starfarer_obf.jar`
из проверенного локального backup: изменённые файлы модпака содержали цикл размера текстуры
и ошибку приведения типа окна модов. Изменённые копии сохранены отдельно. Тестовая junction
из `.build` обратно на папку модов вынесена за пределы FR-сканирования. Эти исправления
окружения не входят в поставку мода.

## Упаковка и обновление

Player ZIP содержит runtime JAR и установочные файлы; исходники и инструменты остаются
в репозитории. Проверены CRC, точный inventory 17 файлов, payload manifest на 16 файлов,
все SHA-256 и совпадение упакованных bytes с исходными player-файлами. Packaging fixtures
отвергают изменения после build; source manifest проверяется отдельно.

`StarsectorPrepatcher-0.18.7.zip`: 2 890 831 bytes, SHA-256
`b929b653fde9c3673e682f6c5af2b17231a54fb03a6d729802688148a749d125`.
Архив сопровождается отдельным `.zip.sha256`. Описание выпуска использует формат 0.18.4.

Для 0.98.5a нужен Faster Rendering 1.0.0 или новее; после обновления FR следует пересоздать
конфигурацию Mikohime. Поддержка новой игры объявлена в
[1.0.0rc1](https://github.com/Halke1986/starsector-render/releases/tag/v1.0.0rc1), проверен
[1.0.0](https://github.com/Halke1986/starsector-render/releases/tag/v1.0.0). Отдельный
`fr.agent.jar` в новом FR не требуется. Metadata мода указывает `0.98.5a-RC3`;
на поддерживаемой `0.98a-RC8` возможно предупреждение о другой patch-версии.

## Границы проверки

Ручной игровой прогон подтверждён для Windows 0.98a-RC8; полный GUI/campaign прогон
новой игры и Linux отдельно не заявляется. Новых A/B-измерений производительности нет.
Антивирусный результат прежнего архива не переносится на 0.18.7. Raw diagnostics
остаются в `.build/`; reusable gates принадлежат [VALIDATION](../VALIDATION.md).
