# Отчёт о выпуске 0.18.6

## Итог и состав

Патч-релиз исправляет Windows install/uninstall для Mikohime. Оригинальный Mikohime
обслуживается нашим установщиком; конфигуратор Gaius со встроенным подключением Prepatcher
распознаётся отдельно и получает инструкцию включить или отключить агент через
`Configure_Me.cmd`, без правки его файлов и ложной ошибки об отсутствии `DefaultVM`.
BAT и оба README уточняют выбор отдельного Faster Rendering launcher и удаление агента.
Управляемая запись агента распознаётся во всех трёх поддерживаемых формах кавычек.

Точная граница владения файлами и структурные признаки описаны в
[COMPATIBILITY](../COMPATIBILITY.md#windows-mikohime-владелец-конфигурации).
Исходники runtime отличаются от 0.18.5 только номером версии агента; transformation surfaces,
порядок pipeline, fail policies, набор `patch.*` и значения профилей не изменены.
Сохраняется Scheduler Fork `1.0.14-spp13`, bridge V10, required mask `0xbff` и полный
UI/restore contract `0xfff`. Новый runtime или выпуск форка не требуется.
Нового ускорения этот релиз не заявляет.

## Выполненная валидация

До упаковки пройден [Windows installer gate](../VALIDATION.md#windows-installer-gate):
16 сочетаний Gaius layout/state, включая исходные `Configure_Me.cmd` из upstream
`v0.7.6` и `v0.8.1`, сохранили все файлы при install/uninstall. Проверены комбинированный
выбор и `All`, original install/reinstall/uninstall, совпадение backups с исходными файлами,
сохранение чужого агента и настроек памяти, генерация с legacy FR, FR agent и отключённым FR,
а также отказ missing/unknown layout до записи. Запускались только синтетические генераторы;
upstream scripts и игра не запускались.

- Полный Windows `verify-structural.ps1` на чистых 0.98a-RC8 JAR и Java 17/`27+22`
  завершился с кодом 0: structural/runtime, реальные AoTD fork/ownership, optional-mod,
  idempotency/rollback, startup, hyperspace и legacy FR проверки прошли.
- Полный Linux `verify-linux.sh` в отдельном каталоге Ubuntu VM завершился с кодом 0:
  canonical/native pipeline, shell и packaging fixtures, ShellCheck, Java 28 + FR runtime,
  XML/Preferences и реальный AoTD child-loader handshake `0xfff` с exactly-once restore.
- Пересобранные Windows JAR имеют тот же inventory entries, что и 0.18.5. Agent отличается
  только строками версии в manifest и `PrepatcherAgent.class`; bootstrap — только manifest.
  Остальные entries совпадают побайтно.
- Финальный ZIP содержит ровно 17 файлов. Проверены CRC, точный состав 16 записей payload
  manifest, все SHA-256, совпадение payload с исходным деревом и версия 0.18.6 в metadata
  и manifest обеих JAR. Developer files и новая installer test suite в архив не попали.

## Упаковка и обновление

Игрок получает готовые JAR и Windows/Linux launch scripts. Source, tests, developer tools,
внутренняя документация и диагностические результаты в ZIP не входят. Source manifest
проверяется до упаковки, а архив содержит отдельный manifest своего payload.
При обновлении нужно закрыть игру и заменить папку мода. Пользователь Gaius включает
Prepatcher в его конфигураторе; оригинальный Mikohime использует наш BAT.

Размер `StarsectorPrepatcher-0.18.6.zip` — 1 838 955 bytes. SHA-256:
`7b6aac0817a3aa825516e59cbf7ac1005997f50b2f4700ae52fd1c49b214b95e`.
GitHub release description использует структуру 0.18.4: дата, What's New, Compatibility
и ссылка на этот отчёт. Архив сопровождается отдельным `.zip.sha256`.

## Границы проверки

Runtime-контракт наследуется от 0.18.5. Проверки используют чистые Windows/Linux игровые
JAR и изолированные fixtures; установленный modpack core не является release baseline.
Ручной GUI-прогон и новое измерение производительности не заявляются. Антивирусный
результат ZIP 0.18.5 не относится к новому архиву. Raw diagnostics остаются в `.build/`.
