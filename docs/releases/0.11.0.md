# Отчёт о выпуске 0.11.0

Дата: 2026-07-24.

## Назначение

`0.11.0` завершает production-интеграцию с AoTD Scheduler Fork и уменьшает стоимость
обработки рынков, которые существуют только для planet conditions. Выпуск сохраняет
fail-open модель: без полного handshake используются исходные vanilla-пути, а потеря
runtime capability отключает только зависящую от неё оптимизацию.

Для Starsector требуется оригинальный `starfarer.api.jar`. Устаревшая модифицированная
копия из ранних сборок AoTD несовместима с этим контрактом и не должна устанавливаться.

## AoTD Scheduler Fork

### Полный native-профиль

- `BaseIndustry.getMaxDeficit()` получает clean wrapper с сохранённой vanilla-реализацией.
  Priority-deficit semantics включается только после полного native handshake.
- Production capability mask расширена до `0x1ff` за счёт
  `RUNTIME_EPOCH_COORDINATION`.
- `SchedulerBridge` schema V6 преобразуется в прямые loader-safe вызовы runtime bridge:
  публикацию campaign/economy epoch и чтение актуальной capability mask.
- Explicit `AOTD_NATIVE` commodity temporal mode связывает availability, excess,
  deficit и trade stats с существующими mutation hooks. Пустые temporal maps переводят
  запись в спящий режим до следующей релевантной мутации.
- Reflection-accessors для AoTD temporal stats кэшируются через unload-safe `ClassValue`
  и не создают process-lifetime strong root на mod classloader.

### Revision и epoch contract

Queue membership и causal validation разделены. Prepatcher сохраняет exact dirty mask:

- `DIRTY_STRUCTURE` повышает structural generation;
- accessibility-, trade-, price-, stockpile- и temporal-only bits не повышают её;
- вложенные mutation boundaries объединяют masks и публикуют structural generation
  не более одного раза при закрытии внешней границы.

При публикации новой campaign/economy epoch очищается loader-neutral market state и
очередь старых событий. Открытая global boundary инвалидируется; её поздний callback
учитывается диагностикой, но не может изменить generation новой кампании.

### Live capability downgrade

Runtime остаётся источником истины для negotiated capabilities. Если delivery listener
отключается после `LinkageError`, `NATIVE_DELIVERY_EVENTS` немедленно удаляется из mask.
AoTD видит изменение при следующей capability-проверке, один раз синхронизирует
пропущенные market generations и затем использует fallback dirtying.

## Market scheduler

Для condition-only рынков вне economy due-решение теперь принимается до добавления в
batch touched list. Стабильные policy inputs кэшируются и перепроверяются через bounded
audit; staggered phase распределяет работу между render batches. При этом:

- economy markets, достигнутые через condition call site, сохраняют точную покадровую
  hot-policy;
- первый due batch определяется стабильной phase без специального немедленного вызова;
- reentrant condition delivery сохраняет exact accumulated amount;
- non-economy delivered-time callbacks не загрязняют AoTD market registry;
- новые counters разделяют policy audits/cache hits, due checks/entries, not-due skips
  и фактически добавленные touched entries.

Это изменение не затрагивает `Market.advance(F)V` и его semantic wrappers: оно меняет
только планирование уже накопленного condition-source debt в
`StarsectorPrepatcherHooks`.

## Конфигурация и диагностика

Основной `prepatcher.properties` снова соответствует production/aggressive baseline.
Дорогие observers, CSV/stack sampling, verbose presentation output, metrics и
периодическая stats-задача остаются только в `profiles/debug.properties`.

Четыре Windows BAT-обёртки заменены единым `StarsectorPrepatcher.bat`. Англоязычное
интерактивное меню объясняет сборку, установку, удаление и полный release gate;
установка/удаление отдельно предлагают Vanilla, Faster Rendering или оба launch path.
Для автоматизации сохранён CLI-режим.

Разрозненные промежуточные/hotfix/audit документы удалены из поставки. Актуальные публичные
контракты находятся в `docs/PATCHES.md`, `docs/COMPATIBILITY.md`,
`docs/VALIDATION.md` и этом отчёте; исторические изменения — в `CHANGELOG.md`.

## Проверка выпуска

Release gate включает:

- documentation consistency, версии, ссылки и SHA-256 inventory;
- AoTD bridge schema V6, production mask `0x1ff`, прямой epoch bridge и ASM verify;
- domain-revision regression для non-structural, structural и nested dirty masks;
- stale global-boundary rejection после смены epoch;
- end-to-end `LinkageError` downgrade, mask `0x1ff -> 0x1fd` и однократную
  resynchronization;
- condition-only cadence, economy-through-condition hot path и reentrant delivery;
- повторную трансформацию, runtime payload inventory и startup smoke.

Полный набор запускается через `StarsectorPrepatcher.bat verify` на Windows или
`./verify-structural.sh` на Linux/macOS. Отчёты создаются только в `.build/reports/`
и не входят в релиз.

На референсной Windows-установке 2026-07-24 полный gate завершён успешно:
проверены 42 transformed classes и 2468 методов, runtime payload из 87 классов,
startup javaagent и реальный classloader Faster Rendering.

## Обновление

1. Заменить каталог предыдущей версии целиком.
2. Убедиться, что используется оригинальный `starfarer.api.jar`.
3. Перезапустить игру: javaagent не поддерживает горячее обновление.
4. Для обычной игры использовать `prepatcher.properties`; debug-профиль включать
   только на время сбора диагностики.
