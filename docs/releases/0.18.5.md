# Отчёт о выпуске 0.18.5

## Итог и состав

Патч-релиз объединяет изменения `main` после `v0.18.4`, исправления Linux-инструкции и
пользовательскую упаковку. Предварительный номер разработки `0.19.0` заменён на `0.18.5`;
отдельного опубликованного выпуска 0.19.0 не было. Работы roadmap в состав не добавляются.
Набор `patch.*`, значения production/safe/aggressive/debug профилей и V10 ABI сохранены.
Нового измеренного ускорения эта версия не заявляет.

## Совместимость AoTD и сторонних модов

Обычный AoTD ToT больше не получает вызов fork-only `SchedulerBridge` при строительстве чудес.
`AoTDForkCompatibilityTransformer` проверяет resource/CodeSource provenance, loader ancestry и
полный текущий bridge contract перед изменением construction boundary. Неподтверждённый
upstream-класс остаётся неизменённым с `NOT_APPLICABLE_UNOWNED`; ошибки исходного construction
method сохраняются. Bridge matcher также доказывает `acceptMarketMutation` и
public/static/concrete callbacks. Точные поверхности и ownership-контракт находятся в
[COMPATIBILITY](../COMPATIBILITY.md).

Проверки market-share inheritance, dormant-industry eligibility и custom entity equality больше
не выбрасывают `LinkageError`, если посторонняя сигнатура модового метода ссылается на отсутствующий
тип. Используются прежние консервативные исходы probes; ошибки исполняемых модовых методов не
подавляются. Symbolic-reference audit проверяет новые optional-mod зависимости core bytecode.

Поддерживается Scheduler Fork `1.0.14-spp13`, bridge V10, required mask `0xbff`, полный
UI/restore contract `0xfff`. Код форка и ABI не изменены; development metadata, README и
packaging gate соседнего репозитория согласованы с Prepatcher `0.18.5`. Опубликованное
требование spp13 к 0.18.3 остаётся в той же ветке совместимости 0.18.x. Новая версия форка
и замена его опубликованного архива для этого изменения не нужны.

## Перестройка и композиция

Matchers доказывают контракт до изменения bytecode; `mutate` работает на отдельном candidate,
`verify` проверяет полный post-state. Реализации вынесены из `PrepatcherTransformer` по
подсистемам. Семь hyperspace-патчей используют ту же форму. Presentation pass сохраняет
декларативную оболочку; решения — [D-PATCH-SHAPE](../../decisions/D-PATCH-SHAPE.md) и
[D-PRESENTATION-ENVELOPE](../../decisions/D-PRESENTATION-ENVELOPE.md).

Пересекающиеся поверхности собраны в `strategicJumpDestinationPlan`, `campaignListenerPlan`
и `mapInteractionPlan`: общий matcher, candidate, marker/mask и combined postcondition дают
атомарное применение и отказ всей запрошенной группы. Существующие kill switches сохранены.
Descriptors, регионы методов, допустимые masks и порядок определены в
[COMPATIBILITY](../COMPATIBILITY.md) и
[D-MERGE-ORDERED-GROUPS](../../decisions/D-MERGE-ORDERED-GROUPS.md).

Pipeline больше не выводит исход текущего вызова из process-wide properties. Диагностика
транзакционна: повторный отказ не теряется, параллельный вызов не отменяет чужой класс,
предварительный успех при откате получает `ROLLED_BACK_PIPELINE`. `DynamicParticleCleanup` и
`ShipAdvanceScratch` доказывают receivers до мутации. Runtime-компоненты разнесены по владельцам
состояния, lifecycle cleanup и диагностики с сохранением generation/reentrancy и public ABI.

## Linux и Java

Сборка распознаёт плоский Linux layout с JAR рядом со `starsector.sh`. Нативные имена классов
Linux отличаются от Windows; build преобразует чистые Linux JAR в canonical compile namespace,
а runtime pipeline переводит целевые классы туда и обратно внутри общей транзакции. Таблица
`linux-0.98a-RC8.tsv` входит в agent JAR. Это устраняет ошибку компиляции с отсутствующим
`com.fs.starfarer.campaign.E` из пользовательского отчёта. Platform/bootstrap классы, включая
`org.xml`/`org.w3c`, исключаются по loader ownership до game-bytecode parsing.

Игрок получает готовые JAR и не компилирует исходники. Оба README разделяют Windows и Linux,
требуют папку `StarsectorPrepatcher` без `-dev` и показывают `./mods/...` из Linux-каталога
игры. Аргумент добавляется в существующую команду Java до `-classpath`, с сохранением `\`;
новая shell-команда `-classpath` не создаётся. Miko/FR launcher сохраняет `Miko_Simple.txt`
и порядок agents. Для запуска нужен только Java runtime; `javac`/`jar` требуются сборке и
проверкам из checkout. Автоматические Linux install/uninstall adapters не добавляются.

## Упаковка и обновление

ZIP содержит 17 файлов: runtime JAR, metadata/config, профили, license, README, logs guidance,
установочные/пользовательские launch scripts и их helper, а также payload manifest. Source,
tests, build/verify/release tools, development dependencies, внутренняя документация и GIF
остаются в Git. BAT содержит установку, удаление и справку. Исходный manifest проверяется
перед упаковкой; ZIP получает отдельный manifest только для своего payload. Готовые релизные
ZIP и их внешние `.sha256` не становятся зависимостями исходного дерева обоих builder-ов.

Размер итогового ZIP — 1 838 031 bytes. SHA-256:
`164b537a203ed78e9f084617a4fe785f1fa044c39e2ec1ac65da9e131808768e`.
Причина эвристических обнаружений старой поставки описана в
[отчёте 0.18.4](0.18.4.md#переупаковка-для-игроков-2026-11-10).
Обновление не требует изменения игровых JAR или сохранений; игру перед заменой мода закрывают.

- Полный Windows `verify-structural.ps1` на Java 17 и `27+22`, чистых backup core JAR: structural/runtime,
  реальные fork/ownership/optional-linkage проверки, startup, hyperspace и legacy FR.
  Устаревший вызов удалённого destination-first теста заменён актуальным
  `StrategicJumpDestinationPlanTransformerTest`, как в shell gate; проверки не удалены.

  structural regression (49 классов / 2637 методов), 24 presentation targets, native pipeline
  (73 targets), ASM/idempotency/rollback, 138 runtime payload classes и real-fork gates.
- На Temurin `28-ea+13` с реальным FR agent пройдены actual-agent runtime linkage,
  DOM/SAX/transformer/Preferences и parent-game/child-mod AoTD handshake: `0xfff`,
  construction-before-handshake и restore callback ровно один раз.
- Windows-built JAR из итогового ZIP отдельно извлечён и проверен в том же Linux Java/FR
  runtime, включая 138 payload classes, 73 native targets, XML/Preferences и реальный AoTD.
- Shell fixtures: flat/split layouts, пробелы, обычный многострочный `starsector.sh`,
  runtime-only PATH без compiler tools, сохранение Miko settings и порядок agents.
- Windows install/reinstall/uninstall из итогового ZIP для Vanilla и Faster Rendering;
  идемпотентность и сохранение другого agent. Все CRC и payload checksums совпали.
- Packaging regression: developer files отсутствуют, extracted payload manifest точен,
  устаревшие source checksums останавливают упаковку. ShellCheck и documentation gate прошли.
- [VirusTotal итогового ZIP](https://www.virustotal.com/gui/file/164b537a203ed78e9f084617a4fe785f1fa044c39e2ec1ac65da9e131808768e),
  анализ 2026-11-10: 0/71 detections, 62 undetected и 9 unsupported. Microsoft `1.26100`,
  signatures `20261110`: `undetected`. Публикуется именно этот проверенный ZIP.

## Границы проверки

По решению владельца release validation использует только чистые игровые JAR Windows/Linux,
не модифицированный core установленного modpack. Synthetic mutation/negative fixtures
сохранены. Автоматические проверки не являются gameplay/performance benchmark. Ручной GUI-прогон
рынка, торговли, строительства и save/reload этой версии не заявляется выполненным.
Другие Java/FR сборки требуют своей проверки; отсутствие антивирусных обнаружений относится
к указанному образцу и дате. Raw diagnostics остаются в `.build/reports/` и не коммитятся.
