# Отчёт о выпуске 0.19.0

> Project home:
> [StarsectorPrepatcher — overview, installation and downloads](https://github.com/kirpoly/StarsectorPrepatcher)

## Итог

Выпуск не меняет пользовательского поведения. Ни один патч не добавлен, не удалён и не изменён по
существу: набор ключей `patch.*`, их семантика и требования к установке те же, что в
`0.18.4`. Версия поднята потому, что внутреннее устройство перестроено полностью, и отличать его от
предыдущего состояния по номеру удобнее, чем по дате коммита.

Отдельно исправлена диагностика и обработка отказов внешнего pipeline: повторный отказ больше
не пропускается, отказ другого вызова не отменяет текущий класс, а отменённый успех получает
`ROLLED_BACK_PIPELINE` вместо `APPLIED`.

## Что перестроено

**Владение runtime-состоянием.** CampaignCaches координирует смену поколения, а компоненты сами
отсоединяют свои карты и thread-local roots. Управляющее состояние scheduler остаётся вместе;
diagnostics/observers вынесены за immutable snapshots без доступа к его mutable state. Числовые
gauges Intel/Map/Scratch также собираются владельцами. Порядок доставки, generation/reentrancy,
TTL/grace и process-lifetime регистрация сохранены. Границы описаны в
[PATCHES](../PATCHES.md#campaign-cache-maintenance-and-scratch-retention), проверки — в
[VALIDATION](../VALIDATION.md#сначала-зафиксировать-время-жизни-и-ownership).

**Форма патча.** Патч был одним методом, который одновременно искал место, решал о применимости и
вносил правку. Теперь это три фазы с разными обязанностями: `match` доказывает контракт и ничего не
меняет, `mutate` применяет доказанный план, `verify` проверяет, что должно быть верно после. Решение
и отвергнутая альтернатива записаны в [`decisions/D-PATCH-SHAPE.md`](../../decisions/D-PATCH-SHAPE.md).

**Размещение кода.** `PrepatcherTransformer` содержал 12 276 строк: 73 патча и 457 общих помощников
в одном классе. Помощники вынесены, патчи разложены по одному на файл и сгруппированы по игровым
подсистемам — тринадцать подпакетов вместо одного плоского.

**Композиция.** Три пары патчей с пересекающимися transformation surfaces применялись по порядку, а
не сливались, что нарушало первое правило композиции в `AGENTS.md`. Теперь это три атомарных плана,
и порядок применения внутри группы ни на что не влияет:
[`decisions/D-MERGE-ORDERED-GROUPS.md`](../../decisions/D-MERGE-ORDERED-GROUPS.md).

**Вторая обёртка.** `applyHyperspace` была частичной версией той же идеи и удалена; семь патчей,
ходивших через неё, переведены в общую форму. Декларативная таблица
`FastForwardPresentationTransformer` сознательно оставлена своей оболочкой — она уже доказывает
контракт до мутации, работая на клоне, а отличается устройством транзакции, а не формой патча:
[`decisions/D-PRESENTATION-ENVELOPE.md`](../../decisions/D-PRESENTATION-ENVELOPE.md).

**Стиль.** Введён закреплённый профиль форматирования (Eclipse JDT, библиотеки скачиваются по
требованию с проверкой SHA-256), и дерево переформатировано механически. Отступы занимали 20,7 %
символов кодовой базы, стало 9,3 %.

## Исправлено

Дефект, найденный ревью по ходу перестройки: в `DynamicParticleCleanup` и
`ShipAdvanceScratch` применимость получателя устанавливалась **после** мутации. Транзакция не
позволяла выпустить испорченный результат, но план возвращался для формы, которую мутатор затем
отвергал. Доказательство перенесено в `match`, и оба случая закрыты тестом
`ScratchReceiverApplicabilityTest`, который идёт под гейтом.

Дефект существовал потому, что его ничто не проверяло; тест добавлен вместе с исправлением.

`OrderedTransformerPipeline` больше не сравнивает process-wide properties для принятия решения.
Отказ передаётся явно в контексте текущего вызова; положительные статусы, сообщения и счётчики
публикуются после commit. Поздний отказ сохраняет его причину и отменяет предварительные успехи.
Повторный, вложенный и параллельный вызовы закрыты регрессиями внутри существующего pipeline gate.
Контракт описан в [COMPATIBILITY.md](../COMPATIBILITY.md#classloader-архитектура-и-faster-rendering).

## Устранено в проверках

Гейт `verify-structural` не проходил целиком и останавливался на первой проверке. Причины были в
самих проверках, не в продукте, и все относились к веткам, которые никогда не выполнялись:

- легаси-раскладка Faster Rendering включалась по одному лишь наличию `fr.jar`, хотя современные
  сборки FR не содержат легаси-загрузчика;
- рантайм для маршрутов Java 27+ искался по жёстко зашитому каталогу `jdk-27+22`, тогда как код
  разделяет маршруты по `feature ≥ 27`;
- в classpath маршрута FR-агента не было log4j, а сам маршрут запускался не из `starsector-core`,
  хотя агент FR читает `starfarer_obf.jar` по относительному пути;
- повреждённый `fr.jar` давал успешный `SKIPPED` вместо отказа.

Требования к матрице выпуска приведены в соответствие с тем, что проверяется:
[`docs/VALIDATION.md`](../VALIDATION.md).

## Доказательство неизменности

Каждый шаг перестройки сверялся с предыдущим состоянием по множеству строк статусов патчей
**вместе с текстом причин**: какой патч, к какому классу, с каким исходом и по какой причине.

До исправления pipeline при перестройке наблюдались только намеренные изменения — три новых
идентификатора атомарных групп. Прогон до исправления pipeline: `exit 0`, 91 проверка `OK`, 304 различных строки
статусов.

Отдельно отмечено для истории: часть промежуточных сверок велась по шаблону, который отбрасывал
имена классов с `_` и `$` — то есть патчи Nexerelin, `PK_CMD` и вложенные классы. Двенадцать строк
из 304 в те сверки не входили. Ошибка исправлена, финальные сравнения выполнены по полному шаблону. Равенство статусов означает
одинаковые решения на этих входах, а не доказанное равенство байткода или runtime-поведения;
[уровни доказательств](../VALIDATION.md#уровни-доказательств) различают эти утверждения.

Версия обновлена в `mod_info.json`, `PrepatcherAgent.VERSION`, манифестах обоих build-скриптов и

## Хуки рантайма

Три крупнейших класса в `com/fs/starfarer/api` тоже разрезаны: `StarsectorPrepatcherHooks` с 8 691
строки до 477, `StarsectorPrepatcherRuntimeBridge` с 2 083 до 77, `StarsectorPrepatcherStrategicJumpIndex`
с 1 914 до 892.

Имена и дескрипторы этих методов — то, на что ссылается внедрённый в игру байткод. Но ссылки
пишет наш же код и переписывает при каждом запуске игры; снаружи их не читает никто — ни
сохранения, ни другие моды. Поэтому перенос допустим, если вызывающая сторона переезжает тем же
изменением, и разрезы сделаны именно так.

Два способа при этом различаются, и это стоит знать: `Hooks` сохранил методы-переходники на прежних
именах, а `RuntimeBridge` перенёс точки входа и перецелил вызывающих. Первое незаметно снаружи,
второе требует, чтобы все вызовы были найдены.

Новые классы попадают в игровой загрузчик автоматически: `RuntimeInstaller` берёт всё из пакета с
префиксом имени `StarsectorPrepatcher`. Состав проверяется счётчиком в обоих build-скриптах и в
loader smoke test — 138 классов в актуальной сборке. Число подтверждено сборкой на Ubuntu;
Windows-скрипт синхронизирован с тем же строгим составом.

## Linux development integration

Linux changes were ported onto the current `07833da` implementation rather than replacing
the 0.19.0 pipeline or runtime ownership refactor with the earlier 0.18.4 code. Invocation-local
diagnostics and atomic rollback are preserved; namespace output conversion precedes commit.
The loader-ownership check fixes the Java 28 XML/platform-class parser errors seen in the
first Linux build. Runtime payload count is 138 in both build scripts and loader smoke tests.

Executed on Ubuntu with native 0.98a-RC8, Temurin 28 EA +13 and the Linux Faster Rendering agent:

- canonical structural regression: 49 classes / 2637 methods; presentation: 24 targets;
- native production pipeline: 73 targets, roundtrip, ASM verification, idempotence and rollback;
- all 138 runtime payload classes and 73 native targets resolve in the actual agent route;
- DOM/SAX/transformer/Preferences regression passes without pipeline failures;
- supplied AoTD `1.0.14-spp13` JAR passes market-share, economy-hotpath, construction-boundary,
  scheduler-bridge, UI economy behavior and marker-scanner checks;
- actual Linux parent-game/child-mod handshake is ACTIVE with `0xfff`; the restore callback
  is delivered exactly once and native economy classes resolve;
- shell fixtures, ShellCheck and documentation/checksum validation pass.

The Windows build also completes with 138 payload classes. Structural checks against clean
Windows backup JARs pass (49 classes / 2637 methods). The full gate against the locally modified
Windows modpack stops at the `intelArrowRendering` structural mismatch in `coreui/A/Z`; this
is not evidence of a passing full Windows-modpack gate, and that separate patch surface was
not changed by the Linux port.

The development fork's launcher dependency is aligned to Prepatcher 0.19.0: Starsector treats
the former 0.18.x declaration as another compatibility family and otherwise disables the mod.
The fork version and V10 ABI are unchanged. Game core JARs and user patch settings are preserved;
the Ubuntu deployment includes backups of saves, configuration and the previous Prepatcher.
The user loaded the existing test campaign without overwriting saves. Its live log confirms
AoTD `1.0.14-spp13` enabled and the `0xfff` contract active; Prepatcher's session log contains
no ERROR, WARN, SKIPPED or rollback entries. Economy fleets/missions continued after loading.
The game log still contains the same FR/resource-loader startup errors also present before
AoTD installation (`flare`/`module_hightech_decor`, eager LocalResources initialization and
BaseSpawnPoint); these are not the fixed namespace exceptions. Market/trade/building UI,
save/reload and representative performance measurements remain unverified. No GitHub release
has been published.

## Unreleased: upstream ToT construction and optional-linkage audit

The reported Prepatcher 0.18.4 / upstream ToT 1.0.11 crash was caused by our construction-start
transformer inserting a fork-only `SchedulerBridge` reference after matching an upstream method.
The defect also remained in the development 0.19.0 tree. Structural method similarity was not
proof of fork ownership. The transformer now verifies same-CodeSource resource provenance,
loader ancestry and the existing current fork/bridge ABI before mutation. Ordinary ToT remains
unchanged with `NOT_APPLICABLE_UNOWNED`; no new version pin, mod dependency or configuration key
was introduced. See [COMPATIBILITY.md](../COMPATIBILITY.md) for the governing ownership contract.

The audit covered optional-mod symbolic references in transformer sources, bridge-generated calls,
AoTD runtime eligibility/dispatch probes and the Nexerelin/Faster Rendering integration surfaces.
No second upstream-class-to-fork-only direct-call defect was found. Bridge matching now also proves
the local `acceptMarketMutation` handoff and public/static/concrete callback methods before emitting
calls. Three reflective eligibility probes did expose another failure mode: an unrelated unresolved
mod method signature could throw `LinkageError` while checking market-share inheritance, dormant
BaseIndustry eligibility or custom entity equality. They now use their existing conservative
outcomes instead of propagating that probe failure. Actual mod method errors are not swallowed.

Executed Windows checks: clean backup core structural gate (49 classes / 2637 methods), new symbolic
optional-reference audit, real-fork construction/bridge/market-share/economy-hotpath/UI checks and
seven runtime contract/restore/revision/Cargo/delivery/UI/child-loader tests passed. The new unresolved
signature fixture reproduced the market-share crash before the fix and all three probes passed
afterward. Construction fixtures cover success and the original exception without a bridge,
incomplete/future contracts, mixed JARs, parent shadowing, missing provenance and invisible runtime.
The full gate on the locally modified Windows core stopped at the Market persistent-snapshot hook
assertion; it is not reported as a full modpack pass. No player save or installed Ubuntu mod was
modified by this audit. GUI construction in the reporting player's exact modpack remains untested.

The complete Linux gate also passed in an isolated temporary copy using native Ubuntu game JARs:
canonical regression, native ordered-pipeline optional-linkage audit, reflective probe regressions,
real-fork gates and actual Java 28 + Faster Rendering runtime checks. The child-loader smoke proves
that the construction wrapper is applied before bridge initialization, followed by ACTIVE `0xfff`
negotiation and exactly-once restore delivery. No tag or release is part of this change.

## Принятые остаточные риски

Счётчик внедряемых классов хранится в трёх местах и правится вручную. За время работы он трижды
вызвал конфликт слияния и один раз поймал арифметическую ошибку — то есть свою задачу выполняет, но
просится быть вычисляемым.
