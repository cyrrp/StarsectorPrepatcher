# Отчёт о выпуске 0.17.2

Дата выпуска: 2026-08-04

Поддерживаемая игра: Starsector 0.98a-RC8

## Область выпуска

`0.17.2` — correctness hotfix для fail-open границы UI market-mutation optimization и точной
пары с AoTD Scheduler Fork `1.0.14-spp9`. Диагностические чтения больше не могут отменить
обязательный исходный fallback до semantic commit или отменить уже завершённую локальную работу
после него.

Bridge остаётся на schema V9. Required capability mask `0x3ff`, declared/full mask `0x7ff`, public
dispatcher и registration descriptors не изменены. Prepatcher принимает только точную пару
V9 / `1.0.14-spp9` / `0x7ff`; идентификаторы `spp4`–`spp8`, будущие версии и частично объявленные
контракты получают negotiated mask `0`.

## Runtime-инвариант

Boolean guard не владеет fallback-вызовом: исходный virtual `nextStep`/`doubleStep`/`tripleStep`
остаётся в вызывающем bytecode и выполняется ровно один раз, когда guard возвращает `false`.

- До semantic commit все proof reads, подготовка payload и диагностические операции находятся внутри
  fail-open границы. Любой их сбой возвращает `false` и сохраняет исходный global call.
- Успешный fork dispatcher или локальный Prepatcher refresh является commit point. После него
  fork/Prepatcher counters и logging выполняются best-effort; их сбой изолируется, boolean остаётся
  `true`, а исходный global call не выполняется повторно.
- Исключения оригинальных setter/industry mutation остаются вне instrumentation catches, выполняются
  один раз и распространяются без подмены.

Такой контракт отделяет решение о корректности локальной замены от observability. Диагностика может
потерять событие, но не может изменить уже выбранную gameplay-семантику.

## Transformation surfaces и композиция

Trade surface остаётся точным регионом `campaign.ui.class.confirmTransaction()V` от
`TradeWrapper.reportPlayerMarketTransaction(...)` до следующего `EconomyAPI.doubleStep()V` и
обновления price multiplier. Сбор immutable bought/sold commodity IDs выполняется внутри guard;
сохранённый исходный `doubleStep()` остаётся единственным владельцем fallback.

Free-port и пять industry branches входят в прежнюю атомарную группу
`patch.uiMarketMutationRefresh`: exact setter/mutator wrappers публикуют one-shot context, а shared
`recreateWithEconUpdate()` helper выбирает локальный commit либо сохранённый global step. Failed
before/after snapshot монотонно отравляет текущий batch и не может быть стёрт последующей успешной
записью.

Порядок независимой detached-Cargo трансформации не изменён:
`TradeMarketMutationTransformer → AoTDDetachedCargoContextTransformer`. Поздний transformer читает
уже преобразованный метод; combined postconditions, rollback и idempotent reprocessing остаются
обязательными. Новых patch switches, capability bits и пересекающихся transformation surfaces нет.

## Owned AoTD fork

Scheduler Fork `1.0.14-spp9` остаётся first-class implementation. Его стандартные economy steps
всегда глобальны, а поддерживаемые UI intents проходят только через прежний public final
`dispatchPrepatcherUiEconomyStep(int, MarketAPI, long, String[])`.

Real-fork gate подтвердил exact marker/version/mask, неизменные descriptors, containment
post-commit diagnostics, global two/three-step multiplicity и отсутствие legacy context consumers.
Future-version и future-override fixtures fail closed для конкретного runtime class. Bridge
по-прежнему не удерживает статические сильные ссылки на `Class`, `Method`, `ClassLoader`, campaign
objects или mod instances.

## Проверка

Выполнен полный `verify-structural.ps1`; он завершился с кодом `0` и включал:

- throwing `CargoAPI.getStacksCopy()`, transaction/stack getters, before/after snapshots и logger до
  commit: guard возвращает `false`, исходный virtual global call выполняется ровно один раз;
- injected fork и Prepatcher diagnostic failures после commit: guard остаётся `true`, исходный
  global call не выполняется;
- exact registration для `spp9` в safe/full profiles и отказ `spp4`–`spp8`, future identifier,
  неверной declared mask и отсутствующих callbacks;
- полный enabled patch order, применение позднего transformer к post-state раннего, combined
  postconditions, idempotence и atomic rollback;
- real `AoTDToolboxTheory.jar`, future-override negative, ASM verification и actual-agent smoke.

Дополнительная fault injection использует скопированный без изменения post-commit helper из
реального fork JAR вместе с реальными coordinator/baseline классами. Бросающие baseline map,
`Scope.close()` storage и Prepatcher `LongAdder` фактически сработали; уже принятый synthetic-Cargo
commit сохранил `true`, `syntheticCargoSkipped=1`, а счётчик global fallback остался нулевым.

Documentation consistency проверила версию `0.17.2`, 29 Markdown-файлов, 84 относительные ссылки и
71 patch scenario. Завершены также полный structural/runtime набор, реальный fork compatibility,
actual-agent smoke и Faster Rendering loader-topology smoke; runtime payload содержит 113 классов.

Остаточный риск offline-проверки: стандартная JVM не может инициализировать обфусцированный
Starsector `Economy` из-за имён, допустимых только в игровом loader. Поэтому fault-injection harness
исполняет точный helper из JAR в минимальном owner fixture, а связь всех ветвей реального
`AoTDEconomy` с этим helper доказывается отдельным ASM gate. Полный campaign smoke остаётся
обязательной проверкой при ручном тестировании сборки.

Raw verifier output принадлежит `.build/reports/` и не копируется в tracked documentation.

## Упаковка и обновление

Source metadata, build scripts, profiles и current documentation синхронизированы на `0.17.2` и
`1.0.14-spp9`. Agent/bootstrap JAR пересобраны штатным workflow с manifest version `0.17.2`, после
чего обновлён `SHA256SUMS.txt`. Fork release gate создал архив
`AoTD-Theory-Of-Toolbox-Scheduler-Fork-1.0.14-spp9.zip` с SHA-256
`242cd67c0f342c0a28526ad21b44bf73caa72492e4e8b25f8c1a4d3ed722683c`.

Обновлять Prepatcher и Scheduler Fork следует одновременно; смешанная пара со старым
`spp4`–`spp8` целиком отклоняется и сохраняет raw/original пути.
