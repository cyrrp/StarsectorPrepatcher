# Отчёт о выпуске 0.18.3

Дата выпуска: 2026-08-17.

## Назначение

Это парный выпуск для AoTD Scheduler Fork `1.0.14-spp13`. Оба мода нужно обновлять
вместе: runtime bridge намеренно принимает только точный идентификатор fork-версии.

Prepatcher исправляет редкий post-load сценарий, в котором мод вызывает
`CampaignEngine.getEntityById()` до того, как XStream присоединит восстановленные star systems.
Vanilla при этом создаёт неполную non-null id map и больше не перестраивает её автоматически;
последующие miss-lookup обходят hyperspace и все системы.

AoTD `spp13` фиксирует один immutable набор quote-invariant входов на весь расчёт цены вместо
повторного чтения campaign state на каждом integration step. Это сохраняет внутреннюю
согласованность одного preview и сокращает работу hot path. Exotic commodities без доступного
origin market теперь сохраняют настроенный exotic multiplier.

## Совместимость

- Starsector `0.98a-RC8`;
- Java 17;
- Scheduler Bridge V10;
- AoTD Scheduler Fork ровно `1.0.14-spp13`;
- required capability mask `0xbff`, declared/full mask `0xfff`.

Bridge schema и capability masks не изменены. Owned fork использует прежние явно проверяемые
dispatcher/restore surfaces; его изменения цены не добавляют override классов Starsector и не
меняют multiplicity virtual economy calls.

## Transformation surface и композиция

Новый `patch.entityLookupIndexRepair` изменяет
`com/fs/starfarer/campaign/CampaignEngine.advance(FLcom/fs/starfarer/util/A/new;)V` непосредственно
после semantic boundary восстановления repository listeners. Matcher также читает private
`rebuildIDToEntityMap()V`, точный вызов этого метода из `getEntityById(String)` и data flow
allocation/population id map. Патч добавляет private transient synthetic boolean и выполняет точный
vanilla rebuild один раз на экземпляр после load; сериализованного состояния и steady full scan нет.

Эта поверхность пересекается с `patch.campaignListenerThrottle`, который заменяет тот же listener
call. Порядок задан явно в transformer: сначала entity-index repair, затем listener throttle.
Repair matcher принимает raw boundary и валидный post-state throttle. Поздний патч работает с
текущими преобразованными bytes; после него общий composition gate повторно проверяет ранний
postcondition. Любая несовместимость откатывает все изменения класса к входным bytes.

Regression coverage включает полный enabled order, применение repair с включённым и выключенным
throttle, combined postconditions, idempotent reprocessing, rejection partial state и structural
tamper, при котором repair fail-open остаётся локальным и не блокирует независимые
`CampaignEngine` patches.

## Owned AoTD fork

Scheduler Fork `1.0.14-spp13` остаётся first-class implementation. Exact marker/version/mask,
dispatcher descriptors, standard global-step multiplicity, restore callback и отсутствие будущих
critical overrides проверяются по реальному `AoTDToolboxTheory.jar`. Future-version и
future-override fixtures fail closed. Loader-safe bridge по-прежнему не удерживает статические
сильные ссылки на `Class`, `Method`, `ClassLoader`, campaign objects или mod instances.

## Проверка

Полный `verify-structural.ps1` завершился с кодом `0` на референсной установке. Gate пересобрал
agent/bootstrap и подтвердил:

- documentation consistency для версии `0.18.3`: 33 Markdown-файла, 88 относительных ссылок и
  73 patch-сценария;
- structural inventory четырёх core JAR: 49 преобразованных классов и 2637 проверенных методов;
- hyperspace inventory: 4 из 4 targets, 123 проверенных метода, 0 ошибок;
- полный structural/runtime набор, strict-current `spp13` negotiation, real-fork compatibility,
  actual-agent smokes и Faster Rendering loader topology;
- применение `entityLookupIndexRepair` через actual agent/FR loader и runtime payload из 113
  классов.

Отдельный fork release gate также завершился успешно: скомпилированы 240 Java sources,
пересобран `AoTDToolboxTheory.jar`, проверены canonical `1.0.14-spp13` metadata, зависимость от
Prepatcher `0.18.3`, bridge symbols, bytecode descriptors и детерминированный состав ZIP. Raw output
Prepatcher остаётся в `.build/reports/` и не переносится в tracked Markdown.

## Упаковка и обновление

Release identity синхронизирована как Prepatcher `0.18.3` и AoTD `1.0.14-spp13`.
Agent/bootstrap JAR и оба `SHA256SUMS.txt` пересобраны штатными workflow. Fork gate создал
`AoTD-Theory-Of-Toolbox-Scheduler-Fork-1.0.14-spp13.zip` с SHA-256
`aee9550cfc3ccb26fa7d89fa1789b24dfdc5eb021413fd9802daa9b892335450`. В GitHub публикуются
отдельные архивы с одним top-level mod directory и внешние `.sha256` файлы.

Смешанная пара со старым fork целиком отклоняется и сохраняет raw/original пути; обновлять оба мода
следует одновременно.
