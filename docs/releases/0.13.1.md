# Отчёт о выпуске 0.13.1

Дата: 2026-07-28.

## Кратко

Исправление устраняет лишний глобальный economy step при открытии походного Cargo, generated loot
и condition-only рынка, повторные вычисления Local Resources tooltip и удержание starfield pool
между поколениями campaign. Поддерживаемый Scheduler Fork выпускается согласованным пакетом
`1.0.14-spp4` и требует Prepatcher `0.13.1`.

## Detached Cargo

Vanilla создаёт временный рынок `fake_market` для отдельного походного Cargo и вызывает
`EconomyAPI.tripleStep()`. Этот вызов не обслуживает настоящий открываемый рынок, но для обычной
экономики выполняет три глобальных `nextStep()`, а для AoTD мог запускать полный секторный refresh.

`patch.campaignCargoNoGlobalEconomyStep` изменяет только доказанную ветку конструктора
`com.fs.starfarer.campaign.ui.class`:

- matcher находит ровно два вызова фабрики `fake_market`, общий boolean branch local и единственный
  `EconomyAPI.tripleStep()`;
- режим должен быть exact enum `CARGO`, а outpost и внешний cargo — отсутствовать;
- exact vanilla skip разрешается только после отдельной проверки финального
  `Economy.tripleStep()/getEconomy()` bytecode и exact runtime-классов `Economy + ReachEconomy`;
- subclass, replacement economy, изменённый game bytecode или неподтверждённый loader сохраняют
  исходный вызов;
- поддерживаемый AoTD получает one-shot token context, который очищается в `finally`; он не хранит
  market, cargo, UI, `Class`, `Method` или `ClassLoader`;
- реальные station/planet markets, colony/admin/commodity UI и остальные вызовы экономики не
  затрагиваются.

Vanilla contract transformer регистрируется после основного structural plan и проверяет именно
его финальный output. Cargo transformer имеет собственный marker и postcondition, повторная
обработка идемпотентна, а partial/malformed state отклоняется целиком.

## Condition-only рынки и generated loot

Два дополнительных неэкономических UI-пути управляются независимыми переключателями:

- `patch.planetConditionMarketOpenNoGlobalEconomyStep` охватывает только начальный
  `Economy.nextStep()` внутри `CampaignEngine.reportPlayerOpenedMarket()`. Condition-only рынок вне
  точной текущей экономики пропускает этот step, но ability/listener callbacks и
  `setCurrentlyOpenMarket()` сохраняются. Реальные рынки, неизвестные замены экономики и создание
  колонии выполняют исходную работу.
- `patch.lootTransferNoGlobalEconomyStep` расширяет доказанную ветку `fake_market` на enum mode
  `LOOT` с настоящим `CargoData`. Salvage создаётся до открытия панели, поэтому удаляется только
  несвязанный глобальный `tripleStep()`.

Поддерживаемый AoTD fork классифицирует ранний opening-market context до `isLiveMarket()` и
возвращается только для condition-only рынков, отсутствующих в `MarketRegistry`. Тот же one-shot
synthetic cargo context обслуживает detached Cargo и generated loot, не удерживая cargo или market.

## Local Resources tooltip

`patch.localResourcesTooltipSnapshot` сохраняет stockpile limit каждой commodity один раз в
call-local row list и сортирует уже вычисленные integer-значения. Поэтому comparator больше не
повторяет виртуальные и потенциально экономически дорогие getter-вызовы.

Для exact vanilla и Nexerelin исходное тело сохраняется в private synthetic raw method. Wrapper
использует snapshot только для известных concrete plugin classes; неизвестный subclass выполняет
raw implementation.

Оба fork-owned AoTD Local Resources plugin вызывают общий source helper. Он использует
`peekSupplyDemandData()` для уже опубликованного состояния без lazy materialization, а при его
отсутствии один раз возвращается к прежнему correctness path. Фильтры, display multiplier,
тексты и стабильный source order при равных limits сохранены. Persistent cache или сериализуемое
состояние не добавлены.

## Owned-fork compatibility

| Поверхность | Статус |
|---|---|
| `AoTDEconomy.tripleStep()` | напрямую поддерживаемая fork-owned реализация; context потребляется до глобальной работы |
| `SchedulerBridge` schema V7 | direct same-loader rewrite `consumeDetachedCargoOpen()Z`; production capability mask `0x3ff` |
| `AoTDCommodityOnMarket` / `AoTDAvailableStat` | fork-owned read-only peek уже опубликованного supply/demand object |
| AoTD и AoTD×Nex Local Resources | два прямых override используют общий call-local snapshot helper |
| будущая schema/override | fail-closed: capability не согласуется либо сохраняется raw path |

Реальный `AoTDToolboxTheory.jar` проверяется, а не заменяется name-only fixture.

## Проверка выпуска

Release gate:

- пересобирает agent/bootstrap с manifest version `0.13.1` и проверяет runtime payload;
- проверяет documentation/version/link/checksum consistency и синтаксис PowerShell/POSIX scripts;
- применяет vanilla Economy contract к raw bytes и к post-state полного основного structural plan;
- проверяет positive, changed-bytecode, idempotent и partial-state fixtures detached Cargo;
- запускает exact/subclass vanilla runtime routing, one-shot/nested/token-mismatch AoTD context и
  actual-javaagent Economy contract smoke;
- проверяет Scheduler bridge V6/V7 compatibility и реальный fork JAR;
- проверяет vanilla/Nex/AoTD tooltip transformation surfaces и отсутствие comparator getter calls;
- проверяет exact game-JAR сценарий condition-only planet → Survey → ruins LOOT → colonization,
  actual-javaagent статусы и порядок `addMarket → tripleStep → advance(0)`;
- проверяет generation reset, old-pool detachment, stale-lease discard и starfield grace boundary
  в default, `-Xint`, C1 и C2-only JVM modes;
- запускает общие structural, runtime, lifecycle/GC, save, hyperspace, startup и Faster Rendering
  regressions.

Release builder включает `baseline/aotd/deficit-scenarios.csv` в POSIX/PowerShell manifests;
semantic-baseline tests не зависят от development checkout.

## Starfield pool lifecycle

`CacheMaintenanceRuntimeTest` больше не передаёт synthetic campaign engine только в production
`WeakReference`. Test fixture удерживает текущий engine сильным полем и ставит
`Reference.reachabilityFence()` перед заменой/финальным reset, поэтому public maintenance dispatcher
реально доходит до starfield grace trim независимо от JIT режима.

Production `StarsectorPrepatcherHyperspaceHooks.ListPool` теперь generation-aware:

- lifecycle reset очищает free deque текущего campaign thread, обнуляет gauges и удаляет его
  `ThreadLocal` value;
- каждый borrowed `PooledList` получает generation lease;
- release после campaign change очищает stale list и отбрасывает его, не создавая free-list root в
  новом поколении;
- pool другого потока не регистрируется в process-lifetime map и лениво очищается при следующем
  обращении после generation mismatch.

Regression дополнительно проверяет old pool detachment, zero gauges и stale-lease discard.
