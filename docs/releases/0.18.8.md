# Отчёт о выпуске 0.18.8

## Итог и состав

Добавлена поддержка Starsector 0.98.5a-RC5 на Windows/Linux с сохранением 0.98a-RC8
и 0.98.5a-RC3. Новые таблицы переводят имена вокруг прежнего ordered pipeline и runtime
payload; канонический namespace остаётся Windows 0.98a-RC8. Windows-таблица содержит
2843 доказанных соответствия классов, Linux-таблица — 2841. Непарные классы изолированы,
неоднозначные пары не угадываются. Выбор по descriptor `CampaignEngine.advance` и отказ
до runtime installation при неизвестном namespace сохранены.

Офлайн-генератор больше не принимает `Objectnew`, `Stringsuper` и аналогичные комбинации
токенов обфускатора за стабильные читаемые имена. Они сопоставляются по структуре.
Поведение optimization-патчей, kill switches, их surfaces и порядок композиции не меняются;
канонические контракты принадлежат [PATCHES](../PATCHES.md) и
[COMPATIBILITY](../COMPATIBILITY.md#native-game-namespaces).

Исправлена граница обратного namespace translation на Java 17–26: уже исправленные FR
имена сохраняются по точной входной identity члена (owner, kind, name, descriptor),
включая declarations и handle references. Dotted spelling сохраняется, если оно само
присутствовало во входе; глобальное исправление имён без FR на Java 17 не включается.
В RC5 это предотвращает восстановление `new.new`/`null.super` вместо
`new_new`/`null_super` в `Ship.initSlotCovers()V` после изменения `Ship.advance(F)V`.
Откат по-прежнему возвращает входные native bytes, а обязательный Java-27+ repair сохранён.

## Загрузчики и поддерживаемый форк

Bridge V10 и поддержка Scheduler Fork `1.0.14-spp13` сохраняются без изменения ABI.

## Выполненная валидация

Player agent SHA-256:
`45b14005ee9a069c3ea9bf6eb4443cd5b9dc4da12c29fb242c3fa3a4323ed41e`.

Игровой кандидат имел SHA-256
`9e65b25b493ebf51ca00af6ba7eeafcc02b46966fc6f23bcb5c5e8c72225aaaf`.
Все 583 исполняемых `.class` финального агента побайтно совпадают с этим кандидатом,
bootstrap JAR также совпадает целиком. Отличаются только переводы строк CRLF → LF в двух
новых namespace-ресурсах; содержимое строк таблиц не изменилось. Финальный JAR повторно
прошёл Windows matrix и Linux actual-agent проверки с FR и без него.

- Офлайн-сопоставление обеих RC5 завершено без конфликтов. Build namespace probe различает
  Windows/Linux RC5 и прежние таблицы.
- Полный Windows `verify-structural.ps1` на чистых RC5 JAR завершился с кодом 0 после
  исправления имён: structural/runtime/hyperspace/startup, negative/idempotency/composition,
  реальный AoTD fork, Java 17 и Java `27+22`.
- Native pipeline RC5 проверил все 73 цели; 72 изменены. Пройдены ASM, textual roundtrip,
  native identity, idempotency, rollback и сохранение ранее исправленных native members,
  включая неизменность всех вызовов `Ship.initSlotCovers` после production pipeline.
- Windows actual-agent matrix Java 17/27 × FR 1.0.0/без FR разрешила все 138 payload-классов
  и 73 native targets без откатов. Проверка сенсорного типа сверяется с реальным getter
  `CampaignFleet`, а не с именем из одного старого namespace.
- Полный Linux `verify-linux.sh` на RC5 с Java `28-ea+13` и FR 1.0.0 завершился с кодом 0:
  canonical/native gates, shell/packaging fixtures, ShellCheck, XML/Preferences и реальный
  AoTD child-loader handshake `0xfff` с exactly-once restore.
- Точный Windows-built agent с указанным SHA-256 прошёл Linux actual-agent route,
  core-worlds, native linkage 138/73, DOM/SAX/XML/Preferences и AoTD отдельно с FR и без FR.
- Windows native pipeline на прежних 0.98.5a-RC3 и 0.98a-RC8 повторно прошёл все 73 цели,
  roundtrip, ASM, idempotency, rollback и новую проверку member spelling.
- Владелец подтвердил работу Windows RC5 на комплектной Java 17 без FR и с FR 1.0.0
  после исправления имён в игровом кандидате. В логе прогона без FR есть работа
  кампании и успешное сохранение; с FR подтверждены загрузка сохранения и работа кампании.

Первый локальный GUI-запуск без FR остановился в XStream из-за отсутствующих в тестовом
argfile module opens. Оба локальных argfile дополнены opens/exports из официального
FR launcher. Это исправление тестового окружения, оно не меняет установщик мода.

## Упаковка и обновление

Metadata указывает `0.98.5a-RC5`. Для ручного прогона в отдельной
Windows RC5 установлена только player-часть Prepatcher; подготовлены отдельные launchers
с FR 1.0.0 и без него, на комплектной Java 17 с heap 4 GiB. Core JAR не заменяются.

Player ZIP `StarsectorPrepatcher-0.18.8.zip`: 3 938 535 bytes, SHA-256
`8c0111b630b8962b24d356be3e4fd30576fbddb9c2477fe4eef0fc16a0d8047d`.
Dry-run упаковка и `scripts/test-release.sh` прошли: только player inventory, проверка
manifest и отказ при изменении входных файлов после build. Исходный checksum manifest
и документационные ссылки также проверены.

## Границы проверки

Ручные Windows RC5-прогоны выполнены только с Prepatcher, без других модов. GUI-прогоны
Linux и состава с AoTD не проводились. Новых A/B-измерений производительности нет.
Поддержка RC4 отдельно не заявляется. Raw diagnostics остаются в `.build/`.
