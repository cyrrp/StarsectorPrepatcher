# D-TEMPMOD-AGGRESSIVE-SEMANTICS — принятое расхождение expiry scheduler с vanilla

**Статус:** ACTIVE
**Установлено:** `0.9.4`, `patch.tempModExpiryScheduler`
**Governs:** `docs/COMPATIBILITY.md` §MutableStatWithTempMods: принятая aggressive-семантика;
`docs/PATCHES.md` §Expiry-aware temporary stats

## Вопрос

`MutableStatWithTempMods` в vanilla пересчитывает временные модификаторы на каждом кадре для всех
записей. Планировщик на ближайший deadline убирает эту стоимость, но плавающая арифметика по своей
природе не даёт побитового совпадения с последовательностью покадровых вычитаний. Требовать ли
точного совпадения — или принять ограниченное расхождение?

## Решение

Расхождение принято в объявленных границах. Гарантируется точный float countdown для текущего
ближайшего deadline, для совпадающих минимумов и для порядка удаления. Не гарантируется побитовое
совпадение для non-min survivors: одно агрегатное float-вычитание на sweep может отличаться на
несколько ULP от всей последовательности vanilla-вычитаний.

Наблюдаемая граница: мод, читающий `TemporaryStatMod.timeRemaining` рефлексией без публичного
`getMods()`, между точками синхронизации увидит последнее материализованное значение.

## Почему не альтернатива

Полное устранение ULP-расхождения требует хранения и воспроизведения всей истории frame deltas —
то есть возврата к покадровой работе, ради устранения которой патч и существует. Величина
расхождения ограничена несколькими ULP на не-ближайших записях, тогда как момент истечения,
порядок удаления и поведение при совпадающих минимумах воспроизводятся точно.

Условие `deferredDays >= scheduledMin` отвергнуто отдельно: оно способно удалить modifier на кадр
раньше vanilla, то есть меняет наблюдаемый момент истечения, а не точность его вычисления.

## Следствия

1. Patch не меняет публичные методы, дескрипторы, тип `Map` и save graph; vanilla-тела сохраняются
   как private synthetic методы.
2. Все synthetic-поля `private transient synthetic`; `writeReplace()` сначала материализует время.
   Поля планировщика не попадают в XML сохранения.
3. После первого публичного `getMods()` конкретный stat навсегда переходит на retained vanilla path:
   внешний код может удерживать и позже менять live map. То же — для subclass owner, нестандартного
   backing-map, внешней смены размера и runtime anomaly. Fail-open локален одному экземпляру
   ([[D-FAIL-OPEN]]).
4. Directed ULP fixtures входят в actual-agent regression suite и не могут быть удалены как
   «избыточные».

## Что этим решением не разрешено

Перенос той же аргументации на другие патчи. Принято расхождение конкретной величины в конкретном
месте, где момент истечения и порядок удаления остаются точными; это не общее разрешение на
приближённую арифметику в hot path.
